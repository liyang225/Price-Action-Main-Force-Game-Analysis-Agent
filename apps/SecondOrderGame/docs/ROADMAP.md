# SecondOrderGame 开发规划

> **⚠ 所有产出标注"专家先验推演，非统计估计"，直至校准数据积累超过阈值。**
>
> 本文件是唯一的开发优先级参考。ADR 是架构决策记录，CONTEXT.md 是术语表，本文件是"做什么、按什么顺序、交付什么"。

---

## 整体节奏

```
P0 基础设施    →  P1 概率引擎（Day 0 可用）  →  P2 推演引擎
     ↓                                              ↓
P3 PA 联动集成                                P4 数据扩展
     ↓
P5 可视化参数界面（独立模块，不阻塞 P0-P4）
```

P0、P1 完成后系统可以"跑起来"但只有先验，无推演。  
P2 完成后系统可以产出应对树。  
P3 完成后用户可在 PA 内使用完整联动流程。  
P4 扩展数据质量。P5 让非开发者可以调优参数。

- P0-8 在系统落地后按收盘调度完成自选池及相关在册板块的一轮采集；表中 (date, code) 无重复，main_in_flow 无 null，历史窗口固定为 40 个交易日。✅ 已对真实市场开启采集（2026-08-16：PA 自选池 16 标的 × 40 交易日入库 615 行；C长鑫 688825 上市前 25 日无数据为真实缺口）；按代码批量拉取（1 调用/代码）+ 8 次/30 秒节流，避开富途资金流接口配额

- P0-10 的统计分母等于当前在册板块数；缺少任一在册板块的指数或周期位置时不得输出伪完整的高潮占比

### P0-4 的前置约束

**规则草案已完成**（ADR-0019）。草案在 `config/sector_labeler.yaml`，理论驱动，阈值待实测验证。

**实测验证流程**（交给工程师前需完成）：
1. 采集板块指数历史 OHLCV（至少 5 个板块，覆盖 2 年）
2. 人工标注 50-100 个板块日（跨冰点/启动/发酵/高潮/退潮均衡分布）
3. 用草案规则跑机器标注，统计一致性
4. 调整阈值使机器标注逼近人工分布
5. 冻结规则：`version: 0 → 1`，计算 `rule_hash`

**核心陷阱已规避**：判定直接从板块指数 OHLCV 出发，**不用情绪指数做阈值映射**。情绪指数（`config/sentiment.yaml`）是给人看的解释性数值；若用它推导周期状态，混淆矩阵 C 会退化成恒等映射，"大模型是噪声传感器"的整个设计随之失效。

### P0-5 的实现要点

阈值全部来自 `config/labeler.yaml`，代码里不得出现任何数字常量。三处最容易写错：

- **无标签日不得兜底为观望**。校验器能拦住配置开关，拦不住代码里硬写的 `else: return "观望"`。
- **震仓与狩猎止损的区分**在支撑边界与成交量方向上互斥（震仓缩量未破位，狩猎放量已破位）。实现时两个条件都要判，漏一个就会大量误分。
- **区分两类不可用**：「规则无法判定」（69,058 行）计入未命中率，「基准/前向数据/停牌窗口不可用」（13,488 行）不进分母。混在一起算会让覆盖率监控失真。

## P1：概率引擎 B/C 类（Day 0 可用，无需标签）

**目标**：Day 0 起即可估计开盘区间分布（B 类）和 T+1 首次触及概率（C 类）。

### 概率类型回顾

| 类型 | 名称 | 需要标签？ | Day 0 可用？ |
|------|------|-----------|-------------|
| A | 主力行为概率（HMM 隐状态） | 是，需 P0 标注器积累 | 否，仅有专家先验 |
| B | 开盘区间经验分布 | 否，价格历史即可 | **是** |
| C | T+1 首次触及概率 | 否，价格历史即可 | **是** |

### 任务清单

| # | 任务 | 关键约束 | 交付物 |
|---|------|---------|--------|
| P1-1 | B 类：开盘区间分布估计 | 分层日块 bootstrap（ADR-0003）；维护两套分布：`intraday_next_bar`（无跳空，午盘决策用）和 `overnight_next_bar`（有跳空，收盘决策用） | `src/probability/opening_distribution.py` |
| P1-2 | C 类：T+1 首次触及概率 | 条件单元分层（波动率分位 × 换手率分位 × 情绪周期位置）；样本不足时先降维，仍不足则返回"数据不足"状态，不返回带警告的数字 | `src/probability/t1_first_passage.py` |
| P1-3 | T+1 闸门计算器 | 输入：B/C 类概率 + 持仓账龄 + 决策点；输出：`executable_actions` 字段（结构化，不由大模型判断） | `src/probability/t1_gate.py` |
| P1-4 | 先验权重追踪 | 每个概率输出携带 `prior_weight` 字段（当前仍由专家先验驱动的比例）；UI 上标注"专家先验推演，非统计估计" | 集成到 P1-1/P1-2 输出 schema |
| P1-5 | 校准基础设施 | 记录每次预测（概率值 + 实际结果）；Brier score 计算；数量未达阈值时拒绝输出校准分数 | `src/calibration/tracker.py` |

**验收标准**：
- 给定任意股票代码，P1-1 和 P1-2 在 3 秒内返回结果或返回"数据不足"
- `prior_weight` 字段在所有输出中存在且介于 0 到 1 之间
- B 类分布两套（intraday/overnight）互不干扰

| P2-6 | 应对树生成 | 三情景（超预期强/符合预期/低于预期）× 参与者行为矩阵；每叶节点包含概率、行动建议、T+1 闸门结果 | `src/reasoning/scenario_builder.py` |
| P2-7 | 提示词文件编写 | `prompt_engine/` 下所有参与者行为 txt（ADR-0011）；参考博弈论推演文档和霍华德马克思二阶思维框架 | `prompt_engine/**/*.txt` |
| P2-8 | 政策环境感知 | 硬信号：沪深300/上证50 ETF 异常放量检测；软信号：直接扫原始新闻文本（title+snippet）匹配业务词（降准/降息/稳市场/降税/释放流动性等，写广写全）；输出注入 policy_multipliers 选择 | `src/reasoning/policy_detector.py` + `config/policy_detector.yaml`（✅ 已完成） |

**验收标准**：
- 给定板块名 + 个股代码，完整推演流程 < 30 秒（含大模型调用）
- 提示词路由：不存在的文件路径被拒绝，不会触发大模型访问文件系统
- 应对树包含三情景，每情景包含 T+1 闸门建议
- P2-2 的信号在一字板（`high == low`）K 线上返回"数据不足"，不返回 0 也不沿用前值

### P2-2 的实现要点

`config/signals.yaml` 的参数来自加密市场日线的优化结果，不是 A 股实测值——与 `hmm_prior.yaml` 的 alpha 同性质。输出必须挂"专家先验推演，非统计估计"标注。四处容易写错：

- **周期已换算过**。配置里的 28 / 10 / 8 是 K_120M 根数，参考文档的 14 / 5 / 4 是交易日。不要再乘一次，也不要以为写错了改回去。
- **`nash.deviation` 是标准差倍数，不是百分比**。文档正文的"2% 偏差率"指带宽观测宽度。
- **`retracement_min` 等为 null 的参数保持 null**。文档没给数值，触发条件就是纯布尔判定。填上就是发明参数。
- **信号是观测特征，不是交易信号**。不合成买卖点，不输出仓位（`usage.emit_position_size: false`，仓位归 PA）。

## 横切关注点（贯穿所有阶段）

**配置版本化**：每次分析记录保存当时的 config 版本号（ADR-0005）。修改任何配置文件前先递增版本号。

**先验权重可见性**：所有 A 类概率输出携带 `prior_weight`，在 UI 中醒目标注"专家先验推演，非统计估计"，直至先验权重降至 20% 以下。

**测试覆盖**：每个模块交付时附带测试，运行 `pytest tests/` 不得有失败用例。接缝与夹具策略见 ADR-0020：外部数据源（富途/Tavily/AkShare）收敛到单一 `MarketDataSource` 协议接口，测试传 fake 实现 + 假时钟，全部离线可测；标注器用 `tests/fixtures/` 的 golden 小样本做回归。当前已有 137 用例（`tests/test_hmm_engine.py` 33 + `tests/test_config_signals_labeler.py` 104）。

⚠ **P0-1 的交付范围含接缝定义**：必须同时交付 `MarketDataSource` 协议与 fake 实现，因为 P0-3/7/8 与 P1/P2 的测试都依赖它。P0-1 应排在包括 P0-8 在内的其他数据任务之前。P0-8 不需要提前运行，也不享有「先跑通再补测试」的例外；系统落地并通过离线测试后再启动真实采集。

**提示词路径登记**：每新增提示词文件同步更新 `config/prompt_routing.yaml` 和使用手册，确保合法路径集合始终完整。
