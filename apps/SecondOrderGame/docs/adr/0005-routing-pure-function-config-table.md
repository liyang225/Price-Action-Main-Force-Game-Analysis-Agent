# 提示词路由是纯函数，但映射表放配置文件而非硬编码

推演流程的第二步是：识别大模型输出的参与者行为标签，按 `(参与者类型, 情绪周期位置)` 路由到对应的推演思路 txt 文件。路由本身必须是无副作用纯函数——大模型无权自行决定读哪些提示词文件，因为那会让路由不可复现、不可测试，且大模型可能要求不存在的文件。这延续了 PA_Agent `route_strategy_files` 的设计。

然而本项目的三层文档体系明确规定：不得在代码或架构文档中硬编码博弈论参数，参数必须通过配置文件注入并支持动态加载。路由映射表（哪种情绪周期位置配哪套推演提示词）是可以随经验积累而调整的配置，若写死在代码里，每次调优都要改代码、走测试、重部署。

因此：路由逻辑是纯函数（代码实现，可测试，参数版本号进分析记录快照），映射表是配置文件（YAML，运行时加载，修改不触发代码改动）。两者正交不冲突——纯函数的约束是「查表返回已知文件、无副作用」，不是「表必须写在代码里」。

## 后果

配置文件版本号必须随每次分析记录一并保存（与 PA_Agent 保存 `strategy_files_used` 的做法一致），确保历史记录可以准确复现当时使用的路由逻辑。提示词 txt 文件路径的合法集合由代码在加载时校验，大模型永远拿不到超出合法集合的文件名。
