# 下方流动性陷阱（trap_down）在 A 股重定义为破位下跌延续

ADR-0025 的校准发现 `trap_down` 方向与文档语义相反，并标注"需单独 ADR 重审"。本 ADR 完成重审并落地。

## 一、问题

文档语义（加密市场）：下方流动性陷阱 = 主力猎杀**空头**止损后拉回，预期**看涨**。

A 股实测（60 只、189,441 根 K_120M）：`trap_down` 触发后**继续下跌**，看涨方向准确率仅 43%（w2），看跌视角 57%。

## 二、验证：加强收回无法转正

假设"收回条件太弱"（`retracement_min: null`，收回退化为 `close > recent_low` 纯布尔），扫描四档收回幅度（`.scratch/business-rules/signal-calibration/trap_scan.py`）：

| retracement_min | 触发数 | w2 方向准确率（看涨） |
|---|---|---|
| null（现状） | 282 | 42.9% |
| 0.01 | 263 | 41.4% |
| 0.02 | 225 | 40.4% |
| 0.03 | 181 | 42.0% |

加强收回**不升反降**，假设被证伪。方向反不是参数问题。

## 三、根因：A 股无做空，机制差异

加密市场"下方流动性猎杀"针对**空头止损盘**——放量破位触发空头平仓，空头回补推动反弹（看涨）。A 股无做空，破位触发的是**多头止损割肉**，割肉盘涌出后主力压更低接筹，价格继续跌。因此"向下破位 + 当根收回 + 放量 + 心理位"在 A 股捕捉的是**破位下跌中继**，不是主力接筹反转。

## 四、决策

`trap_down` 语义从"假跌破反弹（看涨）"重定义为"**破位下跌延续（看跌）**"。看跌视角下 w2 方向准确率 57.1%、w4 54.3%、w8 51.4%，与 `trap_up`（上方假突破回落，看跌）形成对称的看跌信号对。

## 五、连锁改动

`trap_down` 是看跌信号后，它不能再作为看涨的"逆势买入"条件，故同步调整：

1. **`game_signals.py`**：`contrarian_buy` 从 `herd_selling AND (accumulation OR lower_trap)` 改为 `herd_selling AND accumulation`。`contrarian_sell` 不变（`upper_trap` 本就看跌）。
2. **`CONTEXT.md` / `ARCHITECTURE.md`**：流动性陷阱定义区分上下方向；逆势买入公式移除"下方流动性陷阱"。
3. **`signals.yaml`**：`composite_features.contrarian_buy` 同步移除 `liquidity_trap_down`；`liquidity_trap` 段注释记录语义反转。
4. **`prompt_engine/README.md`**：修正"下方流动性陷阱 → 底部买入机会"的错误联动，拆分"狩猎止损（看涨）"与"下方流动性陷阱（看跌）"。

## 六、关键边界：trap_down 与「狩猎止损」不冲突

「狩猎止损」是**行为标签**（六种主力行为之一），由事后标注器 `labeler.yaml` 判定，明确要求前视反弹（`forward_min ≥ 1.5%`），因此**看涨**不变。`trap_down` 是**实时观测特征**（程序计算），看不到未来，只能靠当根形态，实测为看跌。两者分属不同命名空间，取值本就不一一对应（ARCHITECTURE.md §7 已确立的信号名 ≠ 行为标签原则）。

`trap_down` 自此**不再作为「狩猎止损」的盘中证据**——真正的"主力接筹反转"需要前视反弹确认，实时信号做不到。

## 七、什么会让我推翻

若引入更细粒度数据（如盘口逐笔）能证明 A 股存在某种"放量破位后快速拉回"的主力接筹模式，可重新评估下方陷阱的看涨语义；否则维持本 ADR 的看跌重定义。
