# 三情景以开盘口径定义，提示词样例只列真实字段

## 背景

同一组词在两个地方含义不同：

- **应对树分支**（ARCHITECTURE §10.1）用**开盘**特征定义：超预期强 = 开盘爆买 / 大幅高开；符合预期 = 平开 / 微幅高开；低于预期 = 大幅低开 / 核心标的被砸。分支上挂的是 B 类下一完整时段概率与 C 类开盘首触止损概率。
- **9 篇被路由的行为提示词**用**走势/消息**口径描述同一组情景：继续上涨 / 高位震荡 / 开始下跌，触发写成「新增重磅利好」「利空出现或技术破位」。

后果是模型输出的三情景行为倾向描述的是「后续走势」情景，却被显示在「开盘」情景的分支卡片里，与旁边的概率不是同一件事——与 A 类概率那次「52.3% 与 10.7% 分母不同却并排显示」是同一类误导。

第二个问题：提示词样例列了响应 schema 之外的字段（`sub_type`、`confidence`、`stage`、`psychological_analysis`、`trap_warning`、`follow_up_watch` 以及三情景里的 `risk`）。系统提示词会附加 schema 并禁止未声明字段，模型照抄样例会被判不合格，白跑一次纠正重试。

第三个问题：**三情景行为倾向根本没有进入结果**。提示词一直要求 `scenario_expectations`，但响应 schema 没声明该字段，于是每次都被丢弃，应对树的三个分支只能携带同一份 A 类分布——而 §10.2 要求每个情景都给出各参与者最可能的行为。

## 决策

1. **三情景统一按下一时段开盘强弱定义**（收盘决策看次日开盘，午盘决策看 13:00 开盘），分支名即模型三情景行为倾向的键名。9 篇被路由提示词的三情景标题、触发条件与样例按此重写；行为倾向正文保留。模型若仍写 `超预期`，归一化时映射到 `超预期强`（兼容旧输出）。
2. **三情景行为倾向纳入响应契约**：`scenario_expectations`（`trigger` / `behavior_shift` / `behavior_tendency` / 可选 `risk`）。该字段是附加解释，容错处理——坏数据只丢弃，绝不因此打回重试。
3. **提示词样例只列 schema 声明的字段**，避免「照抄即失败」。`risk`（该行为倾向自身的风险/后续）因为是界面要展示的信息而正式纳入 schema。
4. **被路由到 = 必须具备三情景倾向**，并新增测试钉死：凡 `config/prompt_routing.yaml` 路由到的文件，必须含【情景推演】、样例只含真实字段、情景键与 `REQUIRED_SCENARIOS` 一致。这个坑之所以长期存在，就是因为「文件缺段落」不会报任何错。

## 后果

- 应对方案页的三个情景各自显示「行为倾向」与「风险」。此前三个分支携带同一份 A 类分布、无法区分。
- `散户/底部建仓.txt` 与 `散户/理性跟随.txt` 补齐【加载前提】【二阶博弈推演】【情景推演】【输出规范】——这两篇是冰点、启动/发酵真正被读到的文件，此前连架构 §8.4 要求的四层序贯推演都没有。
- `散户/高位减仓.txt` **不补内容**：它不属于任何周期路由，写了也不会生效，避免制造「已生效」的假象。它仍是行为词表成员与对照材料，其判断经由 `理性跟随.txt` 的改判边界体现。
- **未解决（另开议题）**：路由按周期选一篇提示词，等于提前把行为定好，因此「观望」（散户六个行为里通常概率最高或第二高）拿不到任何提示词，`主力/观望.txt`、`散户/观望.txt`、`散户/高位减仓.txt` 三篇永远不会下发。这是路由粒度问题，不是补段落能解决的。
