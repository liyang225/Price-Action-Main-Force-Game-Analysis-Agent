# 情绪指数归属板块层，全市场不设唯一情绪值

早期设计写作「情绪面总指数（基准值 50）」，读起来是全市场唯一一个数值。但板块轮动与跷跷板效应意味着同一天不同板块必然处在不同的情绪周期位置——科技高潮时老登股往往正在退潮。用一个全市场数值无法表达这种分化，而分化恰恰是本系统要捕捉的东西。因此情绪指数归属板块层，每个板块独立计算、独立维护跨日惯性。

## 后果

**成本从 O(1) 变成 O(板块数)。** 每个板块都要独立搜消息、判情绪，因此板块列表的规模直接决定 token 成本与延迟。板块列表因此不取全量（富途行业板块上百个），而是动态构成：自选池所涉板块，加涨跌幅榜前后各若干板块。这样既覆盖持仓，也覆盖「资金正在流入而你尚未关注」的板块。

**市场层剩下的不是另一个情绪指数**，而是政策环境、流动性环境、交易环境、指数走势、涨跌家数——它们是板块情绪的输入。市场层另有一个派生的情绪广度指标，是对所有板块情绪的横向聚合，非重新计算。

**隐状态与行为分属两层。** HMM 的隐状态是板块情绪周期位置，行为是个股主力行为，`W[z,x]` 即「板块情绪周期 → 个股主力行为」。这与「情绪冰点对应主力建仓试盘」的原始设计一致，并顺带解决了跨截面池化的对象问题：在同一板块周期位置下池化该状态的所有个股，样本量才够。

**情绪台账从一行变成 N 行**，每个板块独立维护惯性。台账跨交易日持久化，是一等公民的领域状态，不是分析记录的副产品——这一点是「分析流水线内部不落盘中转」原则的例外，因为惯性必须跨进程重启存活。
