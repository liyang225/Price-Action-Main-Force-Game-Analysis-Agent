# 消息搜索在后台持续填充当日缓存，决策时零等待

消息面数据用富途 `get_search_news` 接口按板块名搜索，限频 10 次/30 秒。按 Q19 设计，在册板块动态维护在 20–30 个之间。若决策触发时才同步拉取，一轮全量搜索需要 60–90 秒，严重阻塞午盘决策点（11:30 仅有 90 分钟午休，延迟不可接受）。

因此消息搜索作为后台任务在盘中持续运行：每 3 秒搜一个板块，结果写入当日分析材料缓存。决策时直接读缓存，零额外延迟。对于富途无法提供或需要更全面资讯的情况，降级使用 Tavily API 补充搜索。

分析材料缓存的生命周期：当日有效，收盘后归档，次日重建。这不是"分析流水线内部落盘中转"——它是一个日级的共享状态，盘中多次分析（多个个股或两个决策点）共享同一份当日缓存，节省重复搜索的 API 配额与延迟。

## 关于消息与个股的关联

用股票代码直接作为 `keyword` 搜索，富途文档未说明是否支持，实测结论未知。采用以下方案规避：用户注册个股到自选池时，同时填写对应的板块名称；后续直接搜板块名，利用返回结果中的 `related_securities` 字段确认新闻与目标个股的关联。不依赖「反查」逻辑，关联关系在入池时由用户显式维护。
