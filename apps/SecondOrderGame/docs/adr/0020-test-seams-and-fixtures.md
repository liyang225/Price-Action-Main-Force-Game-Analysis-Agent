# 测试接缝与夹具策略

## 背景

交付前的最后一个实质缺口。`docs/ROADMAP.md` 关于测试只有一行「每个模块交付时附带测试，运行 `pytest tests/` 不得有失败用例」，而现有代码的测试基础设施状态是：

| 项 | 现状 |
|---|---|
| `src/` | 3 个文件（`config_validator.py`、`hmm_filter.py`、`labeler_constants.py`），38 个模块待建 |
| `tests/` | 2 个文件，**无 `conftest.py`** |
| 导入路径 | 每个测试文件各自手写 `sys.path.insert(0, ...parent.parent / "src")` |
| pytest 配置 | 无 `pytest.ini` / `pyproject.toml` / `setup.cfg` |
| 测试性质 | 全部是纯函数测试（YAML 校验、HMM 滤波），**零个 I/O 测试** |
| 实测数据 | `.scratch/business-rules/experiments/output/daily_ohlcv.csv.gz` 5.9M，无 `.gitignore` |

现有两个测试套件（137 用例）测的都是无副作用的纯计算，所以没有接缝问题。但 P0 全部是 I/O 密集型，每个都有未决的可测性问题：

| 任务 | 未决问题 |
|---|---|
| P0-1 Futu 客户端 | 无 OpenD 连接时能否测？降级路径怎么验？ |
| P0-2 情绪台账 | 临时库还是内存库？跨重启恢复怎么测？ |
| P0-3 当日缓存 | 收盘归档 / 次日重建的日界怎么测？ |
| P0-7 消息预取 | 10 次 / 30 秒限频怎么测？不能真等 30 秒 |
| P0-8 资金流采集 | 40 个交易日窗口、append-only、`(date, code)` 无重复靠什么数据测？ |
| P0-5 个股标注器 | 验收要求复现精确命中分布（建仓 4,279 等），数据集怎么进 CI？ |

这些问题不定，工程师会各自发明方案：一个模块用 `unittest.mock.patch` 打补丁，另一个模块直连真实 OpenD 只在本地跑，第三个模块干脆不测 I/O 路径。结果是 mock 散落各处、CI 依赖外部服务、验收标准无法自动验证。

## 决策

### 一、外部数据源收敛到单一协议接口

富途 OpenAPI、Tavily、AkShare 三个外部数据源共用**一个**协议化接口（`typing.Protocol`），测试传入 fake 实现，真实客户端只在一处适配。

```python
class MarketDataSource(Protocol):
    """所有外部数据的唯一入口。生产实现适配富途/Tavily/AkShare，
    测试实现从固化夹具读取。"""

    def get_kline(self, code: str, ktype: str, start: str, end: str) -> Sequence[Bar]: ...
    def get_capital_flow(self, code: str, date: str) -> CapitalFlow | None: ...
    def search_news(self, keyword: str) -> Sequence[NewsItem]: ...
    def get_dragon_tiger(self, code: str, date: str) -> DragonTiger | None: ...
```

**接缝数 = 1。** P0-1/3/7/8、P1 全部、P2-1/2/8、P4 全部都在这个接缝之上，可完全离线测试。

**为什么是一个而不是三个**：三个数据源在业务上是同一件事的降级链（ADR-0006：富途无法覆盖时 Tavily 降级补充）。拆成三个接口后，「富途失败 → Tavily 接管」这条路径横跨两个接口，测试要同时装配两套 fake，而这恰好是最需要被测的分支。合成一个接口后降级逻辑落在适配层内部，用一个 fake 就能驱动全部分支。

**限频与降级的可测性**：限频器与重试策略不读挂钟，时间源作为构造参数注入（默认 `time.monotonic`）。测试传入可推进的假时钟，10 次 / 30 秒的窗口边界在毫秒内验证完毕，不需要真等 30 秒。

### 二、标注器实测数据集固化小样本

从研究期的 94,594 个「股票 × 交易日」中抽约 2,000 行固化进仓库，作为 golden test 夹具。

**抽样规则**（必须可复现）：

1. 固定随机种子，记录在夹具的 manifest 里
2. 按标签分层抽样，保证六类行为**全部出现**——狩猎止损全量只有 202 行（0.21%），纯随机抽 2,000 行期望命中约 4 行，方差过大
3. 同时抽入未命中行（占比按全量的 73% 保持），因为「无标签日不得兜底为观望」是 ADR-0017 五 明确要求防守的失效模式，需要有样本才能测
4. manifest 记录：源数据哈希、规则哈希（`labeler.yaml` 的 SHA256）、种子、各标签行数

**验收标准的改写**：`ROADMAP.md` 里 P0-5 的验收标准现在是全量绝对数（建仓 4,279、观望 19,401、震仓 561、拉升 479、出货 614、狩猎止损 202，覆盖率 26.99%）。全量数据不进仓库，所以：

- **CI 层**：在 2,000 行样本上复现**分层抽样时记录的该样本的期望命中数**（精确整数，因为规则是确定性的），以及六类标签全部非空
- **本地验收层**：全量数据上复现原始绝对数与 26.99% 覆盖率，由负责人跑一次确认，结果记入交付记录

两层不可互相替代：CI 层防的是「工程师改动阈值或写了硬编码兜底」这类回归，本地层防的是「小样本恰好掩盖了某个分布偏差」。

**为什么不固化全量**：5.9M 压缩数据进仓库本身可接受，但每次规则变更都要全量重标（ADR-0017 的冻结流程第 3 步），产生的 diff 会淹没 review。小样本让回归保护进 CI，全量留在 `.scratch/` 供重标使用。

**为什么不放弃固化**：不固化则 P0-5 的验收标准在工程师机器上无法自动验证，改标注器代码时没有回归保护。而 ADR-0017 已经明确「校验器会拦住配置层面的开关，但如果在代码里硬写兜底，校验器拦不住」——拦这类错误的只能是测试。

### 三、pytest 配置与导入路径

补两个文件，消掉现在每个测试文件手写 `sys.path.insert` 的重复：

1. **`pyproject.toml`**：声明 `src` 为包根（`pythonpath` 或 src-layout），配置 `testpaths = ["tests"]`
2. **`tests/conftest.py`**：集中提供夹具——fake 数据源、假时钟、临时 SQLite、标注器 golden 样本加载器

现有两个测试文件的 `sys.path` 行随之删除。

**`.gitignore`**：新增，排除 `__pycache__/`、`*.pyc`、`.pytest_cache/`、`.scratch/business-rules/experiments/output/`（全量数据留本地）。固化的小样本夹具放 `tests/fixtures/`，不在排除范围内。

## 什么样的测试是好测试

**只测外部行为，不测实现细节。** 这条在本项目有具体含义，因为大量约束是「防静默失效」性质的：

现有 `tests/test_config_signals_labeler.py` 的文件头已经写对了方向——「重点不是『值对不对』（那要靠回测），而是『错误的值会不会被拦住』。配置里的每一条约束都对应一种静默失效：不报错，但信号永不触发或标签被悄悄污染。所以每条约束都必须有一个测试证明它真的会抛错。」

新模块沿用这个标准。对应到各模块的「外部行为」是：

| 模块 | 测的外部行为 | 不测的实现细节 |
|---|---|---|
| P0-2 情绪台账 | 写入后重启进程能读回同一值 | SQLite 表结构、SQL 语句 |
| P0-5 个股标注器 | 给定 OHLCV 输出的标签序列 | 六条规则的求值顺序 |
| P0-7 消息预取 | 限频窗口内不超过 10 次调用；富途失败时 Tavily 被调用 | 内部队列或计时器的数据结构 |
| P1-2 C 类概率 | 样本不足时返回「数据不足」状态而非带警告的数字 | 降维的具体实现路径 |
| P2-3 提示词路由 | 不存在的路径被拒绝；同输入同输出 | 查表用 dict 还是其他结构 |

**必须有测试的失效模式**（这些是 ADR 明确点出的陷阱，校验器拦不住）：

1. 无标签日被硬编码兜底为「观望」（ADR-0017 五）
2. 一字板（`high == low`）返回 0 或沿用前值而非「数据不足」（ADR-0016）
3. 样本不足时返回带「置信度低」警告的数字（ARCHITECTURE 原则三）
4. 板块层标注器读取了情绪指数（ADR-0019 的核心陷阱）
5. 大模型输出被直接当概率数字采信（ADR-0001）
6. 提示词路由产生副作用或接受表外路径（ADR-0005）

### 被测模块与先例

| 先例 | 适用于 |
|---|---|
| `tests/test_config_signals_labeler.py`（配置约束逐条证明会抛错） | P0-6 配置加载校验集成 |
| `tests/test_hmm_engine.py`（纯函数、确定性、无外部依赖） | P1 全部、P2-2 博弈信号、P2-3 路由 |
| 本 ADR 新增的 fake 数据源 + 假时钟 | P0-1/3/7/8、P2-8、P4 全部 |
| 本 ADR 新增的 golden 样本 | P0-5 个股标注器、P0-4 板块层标注器（规则冻结后） |

P5 可视化界面（PySide6）不在本 ADR 的接缝设计内——GUI 测试成本与收益比不同，且 P5 是独立模块不阻塞其他阶段。P5 的测试策略在开工前单独决定。

## 后果

### 立即生效

1. 新增 `pyproject.toml`、`tests/conftest.py`、`.gitignore`
2. 现有两个测试文件删除 `sys.path.insert` 行
3. 新增 `tests/fixtures/` 与标注器 golden 样本 + manifest
4. `ROADMAP.md` 的 P0-5 验收标准拆为 CI 层与本地层两条

### 对 P0 的约束

P0-1 交付时必须同时交付 `MarketDataSource` 协议与 fake 实现，因为 P0-3/7/8 和 P1/P2 的测试都依赖它。这让 P0-1 从「一个数据源封装」变成「数据层的接缝定义」，实现顺序上应排在 P0-8 之外的其他 P0 任务之前。

P0-8 不需要在系统落地前启动，也不享有「先跑通再补测试」的例外。系统完成并通过离线测试后，再按 40 个交易日窗口和约 10–20 只自选股、约 10–20 个在册板块启动真实采集。

### 风险

**小样本可能掩盖分布偏差。** 2,000 行是全量的 2.1%，分层抽样保证了标签覆盖，但不保证边界样本（如震仓与狩猎止损的支撑边界附近）被抽到。缓解措施是本地全量验收作为第二道关，且 manifest 记录种子，发现问题时可换种子重抽扩大样本。

**假时钟测不出真实并发问题。** 限频器在假时钟下逻辑正确，不代表多线程下正确。P0-7 是后台任务，若最终实现用了线程或 asyncio，需要额外的并发测试，不在本 ADR 覆盖范围。

## 不采纳的替代方案

### 方案 A：每个数据源各一个接缝

富途、Tavily、AkShare 各自定义接口与 fake。

**不采纳理由**：接缝数 = 3，测试夹具要写三套。更关键的是富途 → Tavily 的降级路径（ADR-0006）横跨两个接口，测试这条路径要同时装配两套 fake，而它是最需要被测的分支之一。技能与工程惯例都指向「接缝越少越好」。

### 方案 B：在 HTTP / 连接层打桩

不定义业务接口，用 `responses` / `vcrpy` 之类在网络层拦截。

**不采纳理由**：富途 OpenD 是本地网关长连接协议，不是纯 HTTP，网络层打桩要构造二进制协议帧，实现成本远高于业务接口 fake。且这类测试与协议实现细节耦合，OpenD 升级会大面积失效。

### 方案 C：不固化数据，只本地验收

**不采纳理由**：P0-5 的验收标准（复现精确命中分布）在工程师机器上无法自动验证。ADR-0017 已明确「代码里硬写兜底，校验器拦不住」，而这正是最贵的错误之一（观望列膨胀 4.56 倍，解释力归零）。没有 CI 层回归保护，这个错误可能在多次重构后才被发现，届时已积累污染的 W 计数。

### 方案 D：固化全量 5.9M 数据

**不采纳理由**：规则变更需全量重标（ADR-0017 冻结流程），产生的 diff 淹没 review。小样本进 CI + 全量留 `.scratch/` 兼顾回归保护与仓库整洁。

## 与已有 ADR 的关系

- **ADR-0006**（消息预取与 Tavily 降级）：降级链落在单一接口的适配层内部，用一个 fake 驱动全部分支
- **ADR-0016**（信号参数）：一字板返回「数据不足」列入必测失效模式
- **ADR-0017**（个股标注器冻结）：golden 样本的 manifest 记录规则哈希，规则变更时夹具须同步重生成
- **ADR-0019**（板块层规则草案）：板块层标注器的 golden 样本在规则冻结（version 0 → 1）后按同样方式固化
- **ARCHITECTURE 原则三**（不返回带警告的数字）：列入必测失效模式

---

**结论**：单一数据源协议接口把 33 个可交付任务中的 I/O 相关部分全部变为离线可测，接缝数 1；标注器 golden 小样本让 ADR-0017 最贵的失效模式（兜底为观望）获得 CI 层回归保护；pytest 配置与 `conftest.py` 消除现有测试文件的路径拼接重复。测试策略缺口关闭，可交付。
