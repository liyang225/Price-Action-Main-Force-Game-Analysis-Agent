# 情绪分由大模型评分、三情景应对由大模型生成

## 背景

程序词法情绪分使用静态词典（10 个利好词 + 10 个利空词）从标题与摘要匹配情绪方向。该词典覆盖面太窄，绝大多数新闻命中不到词，导致每条消息的情绪分恒为 0，情绪指数失去消息面输入。同时三情景应对方案此前是程序写死的一句话（"闸门通过/数据不足"），不含针对每个情景的实质应对内容。

## 决策

1. **新闻情绪分改由大模型评分**。新增 `通用/新闻情绪评分.txt` 提示词与 `NewsEmotionAnalyzer`：大模型逐条阅读新闻（标题 + 摘要 + 来源 + 发布时间 + 关联板块名称 + 目标证券），输出每条消息的情绪强度 `sentiment_score ∈ [-8, 8]`（带符号强度，非概率）、相关性 `relevance ∈ [0, 1]`、来源可信度 `credibility ∈ [0, 1]`。程序读取后仅叠加确定性「有效期」（发布时间衰减）因子；相关性与可信度优先采用大模型判断，当大模型未输出（或缺省）时回退到程序规则（`related_securities` 匹配 + 来源词表）。`score_to_points` 中间换算已删除，情绪分直接以 ±8 量纲进入指数计算。

2. **B 类下一时段概率永远计算**。下一完整时段分布不依赖止盈/止损价，因此无论是否下单都计算并展示；仅 C 类首达概率在缺失止损价时置空。情景分支不再因"C 类不足"连带丢弃 B 类。观测终点由 ADR-0030 明确为下一根 K_120M 的收盘价。

3. **三情景应对方案由大模型生成**。新增 `通用/情景应对.txt` 提示词与 `ScenarioAdviceGenerator`：大模型针对超预期强 / 符合预期 / 低于预期分别生成一段应对策略文本，程序直接采用（用户选择"全权生成"）。T+1 闸门与可执行动作集合仍由程序计算，作为下单前的最后硬约束，不由大模型决定。

## 对 ADR-0001 / ADR-0009 的修订

原约定「大模型不得生成概率数字、不得计算博弈信号」针对的是**概率与博弈信号**。本决策允许大模型输出两个受控例外：

- 新闻情绪强度 `sentiment_score`（带符号的 [-8,8] 情绪强度，不是概率）、相关性 `relevance`（[0,1]）、来源可信度 `credibility`（[0,1]），仅对 `NewsEmotionAnalyzer` 的请求开放；
- 三情景应对**文本**（建议性文字，非数值）。

实现上，`ModelRequest.allow_numeric_fields` 为受控白名单，只有显式声明允许的字段名（`index`、`sentiment_score`、`relevance`、`credibility`）才能携带数值通过 `_reject_model_probability_numbers` 防线；其余模型输出仍禁止任何数值，混淆矩阵、W 矩阵、B/C 概率与闸门仍全部由程序计算。

## 后果

- 情绪指数消息面不再受静态词典覆盖面限制，但引入了模型调用成本与不可复现性：同一批新闻在不同时刻可能得到不同情绪分。因此情绪指数在审计上标注为「大模型推断」，仍需与程序确定性因子共同记录。
- 相关性与来源可信度改由大模型判断后同样不可复现；程序规则（`related_securities` 匹配、来源词表）保留为缺省回退路径。
- 应对方案文本由大模型自由生成，可能与闸门结论措辞不一致；闸门结论与可执行动作仍以程序计算为准，是下单的最终依据。
- 每板块消息预取上限降为 10 条（富途 `max_count=10` + Tavily 合并去重）。
