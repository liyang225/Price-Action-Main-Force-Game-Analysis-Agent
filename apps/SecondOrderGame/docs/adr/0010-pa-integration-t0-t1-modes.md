# PA 联动：仅 T+1 下单决策自动触发二阶博弈

二阶博弈模块嵌入 PA_Agent 进程，不是独立应用，但在 UI 上是与 PA 技术分析流程并列的独立工作区（见 ADR-0015）。两种运行模式：

**T+0 模式**：自动交易系统仅根据技术分析模块（PA_Agent 阶段1+阶段2）的决策下单。二阶博弈模块不介入下单流程，可独立查看但不阻塞交易。

**T+1 模式**：PA_Agent 技术分析完成阶段1、阶段2 后，只有当阶段2决定下单时才自动启动二阶博弈分析；阶段2决定不下单时结束联动，不运行二阶博弈。二阶分析完成后，PA 输出的结论被路由到二阶博弈决策页面，注入系统提示词，让大模型重新给出技术分析下单可行性判断，并给出全情景应对树。最终下单依据是二阶博弈结论，而非单纯的技术分析。

## UI 位置

> ⚠ **本节已被 ADR-0015 细化。** 「品种栏目中的子标签页」有歧义——PA 已有两层 QTabWidget（工作区层、分析侧栏层），二阶博弈不进这两层任何一层，而是在品种页内部新建**第三层**子标签栏，把 PA 技术分析流程与二阶博弈流程并列为两个独立工作区。详见 ADR-0015。

用户可选择独立运行或 T+1 联动模式。

## PA 阶段 2 输出路由

T+1 模式下，当 PA 阶段 2 决定下单时，其完整 JSON 输出直接路由到二阶博弈模块的大模型输入，不需要用户手动复制粘贴。程序化触发条件是"T+1 模式 AND PA 阶段 2 完成 AND PA 决定下单"；任一条件不满足都不运行二阶博弈。

## T+1 闸门对下单的影响

> ⚠ **本节已被 ADR-0015 修订。** 读过 PA 源码后发现：PA 的 `estimated_win_rate` 只用于显示，下单闸门只看盈亏比（`MIN_RISK_REWARD_RATIO = 1.0`），胜率不参与任何计算。因此「调整胜率影响交易者方程」的机制不成立。
>
> 实际方案见 ADR-0015：二阶博弈输出**独立的布尔闸门 + 理由文本**，作为 T+1 模式下下单前的最后一道判断，不改 PA 的盈亏比闸门。

原始记录（保留以说明设计演进）：~~二阶博弈模块通过调整胜率估计影响"交易者方程"，进而决定是否下单。~~

仍然成立的部分：最终下单与否不由大模型直接输出"买"/"不买"，而由程序化闸门决定。

## 拒绝的方案

- **二阶博弈作为独立应用，手动复制 PA 结论**：用户操作负担大，午盘决策点时间紧迫，流程不可靠。
- **二阶博弈完全替代技术分析**：两个系统互补——技术分析覆盖价格行为，博弈分析覆盖参与者行为，单独使用任一均有盲区。
