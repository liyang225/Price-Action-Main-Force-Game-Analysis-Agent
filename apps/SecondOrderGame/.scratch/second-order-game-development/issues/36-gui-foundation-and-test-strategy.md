# 36 — 交付端到端 HMM 参数工作台（合并 37–40）

**What to build:** 用一条纵向交付链完成可独立启动的 Qt 参数工作台：未保存会话、新手与专家编辑、热力图与生产 HMM 实时预览、保存校验、最近十版历史和可审计恢复。当前项目环境实际提供 PyQt6，沿用 PA Agent 同源运行时。

**Blocked by:** None — 04 与 17 的代码及测试已在仓库中，可直接复用。

**Status:** ready-for-human

- [x] GUI 可加载当前 HMM 参数但不会在打开时修改磁盘配置。
- [x] 未保存编辑存在于独立会话，取消或关闭可安全丢弃。
- [x] 新手模式用中文百分比和弱/中/强信心编辑概率行，自动补偿到 100%，模式切换不丢失修改。
- [x] 专家模式可编辑 A、C、W 全部合法单元和 alpha；非法输入即时说明且不污染最后合法状态。
- [x] 热力图与主力/散户行为分布使用未保存会话实时刷新，行为预览复用生产 `HMMFilter`。
- [x] 保存前调用生产校验；成功时版本自增并原子写入，最近十版可比较、可恢复，恢复形成新版本事件。
- [x] GUI 在常见窗口尺寸可读，错误、未保存、无历史和非法预览均有文字状态，不只依赖颜色。

## Compressed delivery plan

原 37–40 不再作为独立排队单元，全部合并到本票，避免为同一份会话状态、校验路径和 GUI 壳重复搭建接口。它们保留为追踪入口并标记 `wontfix`，含义仅为“被本票替代”，不是取消需求。

## Pre-agreed test seams

- `ConfigSession`：配置加载、未保存编辑、自动补偿、合法状态保护、模式无关性。
- `ConfigHistory`：原子保存、版本递增、十版保留、差异和恢复事件。
- `build_preview`：从会话配置和当前信念调用生产 `HMMFilter`，输出热力图数据与两类参与者行为分布。
- `ParameterWorkbench` 只覆盖关键用户交互的轻量 Qt 测试；颜色、密度、960×620/1440×900 可读性和 Windows 原生行为采用人工截图验收。
