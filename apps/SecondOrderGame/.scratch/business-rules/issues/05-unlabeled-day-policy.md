# 08 — 判不出来的交易日怎么处置

Status: resolved

> 先读 `../BRIEFING.md`。本工单不重述背景。

**What to build:** 一个结论：不满足任何一种行为判定条件的交易日，标注器该输出什么。

三条路，代价各不相同：

**兜底到「观望」**——样本利用率最高，每个交易日都产出标签。代价是观望列的计数被大量「其实是判不出来」的日子填满，W 矩阵的观望行从此失去信息量。而观望是一个有真实博弈含义的行为（主力主动选择不动），把它当垃圾桶会污染这个含义。

**标为无标签、不进计数、但记录覆盖率**——诚实，但可能损失大量样本。好处是覆盖率本身成为一个监控指标：如果它长期偏低，说明工单 03 的规则定得太严，这个信号在兜底方案下会被永久隐藏。

**标为无标签且不监控**——最省事，但察觉不到规则过严。

先用数据回答前置问题：**未命中率到底多高。** 如果只有 5%，三种方案的差别不大；如果是 50%，这个决策决定了标注器有没有用。

如果选择记录覆盖率，还要定义「覆盖率低到什么程度算规则过严」以及触发后的处置流程。注意处置流程里有一条铁律：放宽阈值必须走 ADR 记录原因并重算历史标签，不能悄悄改配置——因为改规则会作废此前累积的计数，静默改动会让新旧标签混在一起且无法分辨。

**Blocked by:** 03 — 六种主力行为的判定规则, 04 — 一天一个标签还是多个

- [x] 实测未命中率：不满足任何条件的交易日占比
- [x] 说明未命中的交易日有什么共同特征（是集中在某类行情下，还是随机分布）
- [x] 给出处置方案的结论及依据
- [x] 若采用无标签方案，给出覆盖率告警阈值及其推导
- [x] 给出覆盖率告警触发后的处置流程，包含「改规则要重算历史」这一约束
- [x] 说明无标签的交易日是否需要单独存档（便于日后规则放宽时回溯重标）
- [x] 评估兜底到「观望」会让该列计数虚高多少倍，用这个数字支撑或否决该方案
