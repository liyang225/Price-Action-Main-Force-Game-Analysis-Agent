# 项目架构文档 — 二阶博弈系统（SecondOrderGame）

> 博弈论框架下基于价格行为与主力行为推算的二阶量化分析模块
>
> **本文件是项目架构的唯一权威描述。** 术语定义见 `CONTEXT.md`，架构决策的理由与被拒方案见 `docs/adr/`，开发优先级见 `docs/ROADMAP.md`。三者不重复：本文件描述「系统是什么样子」，ADR 描述「为什么是这样」，ROADMAP 描述「按什么顺序建造」。

## 1. 系统定位与核心理念

### 1.1 系统是什么

二阶博弈是一个由**程序编排大模型**的量化分析模块，作为 PA_Agent 技术分析系统的姊妹模块，以子标签页形式嵌入 PA 主分析窗口的品种栏。

它不预测价格。它产出的是**情景应对树**：针对下一时段的三种情景（超预期强 / 符合预期 / 低于预期），给出各参与者最可能的行为、对应概率、以及我方的最优反应策略与 T+1 闸门判断。

### 1.2 为什么需要它

技术分析系统（PA_Agent）覆盖价格行为，但有两个结构性盲区：

- **看不见参与者**。同一个「假突破」形态，可能是操纵型主力在猎杀止损，也可能是配置型主力在被动减仓，两者的后续走势完全不同。技术形态本身不携带意图信息。
- **看不见共识的诅咒**。当一个技术信号成为市场共识后，它不仅失效，还会成为反向收割工具。一阶思维关注形态与指标；二阶思维关注「其他人看到这个形态会怎么做，以及主力知道他们会怎么做之后会怎么做」。

二阶博弈填补这两个盲区，并给出「什么时候该有信心，什么时候不该有信心」的量化依据，弥补人性弱点。

### 1.3 三条不可违背的原则

**原则一：程序编排，大模型受约束。** 程序决定步骤、数据、提示词与校验；大模型只在既定约束下作判断并输出结构化 JSON。大模型的合法角色只有三种：输出固定词表内的离散标签、从文本中抽取证据、解释程序算出的结果。大模型**不得**生成概率数字、不得决定读哪些提示词文件、不得计算博弈信号（ADR-0001 / ADR-0009）。

**原则二：不训练，只滤波。** 所有概率参数手写为配置文件，运行时只做前向滤波，永不训练。启动时标注数据为零，任何学习式方法（Baum-Welch、MS-GARCH、结构学习、均衡估计）在 250 根 K 线上都不可识别，且重训会打乱状态标签，摧毁审计性（ADR-0001）。

**原则三：不返回带警告的数字。** 样本量不足时先降维重算，仍不足则返回「数据不足」状态并将对应 T+1 闸门判为不通过。绝不返回一个附带「置信度低」警告的概率值——那会让使用者在压力下自行忽略警告。

## 2. 三层分析架构

系统的分析对象分三层，每层的粒度、职责与产物均不同。混淆层级是本设计最容易犯的错误。

| 层 | 分析对象 | 主要产物 | 更新频率 |
|---|---|---|---|
| 市场层 | 全市场 | 政策环境、流动性环境、交易环境、情绪广度 | 每决策点 |
| 板块层 | 单个板块 | 板块情绪指数（0–100）、情绪周期位置（五档） | 每决策点，跨日持久化 |
| 个股层 | 单只股票 | 博弈信号、主力行为概率、T+1 闸门、应对树 | 按需触发 |

### 2.1 市场层

市场层**不产出情绪指数**。全市场没有唯一的情绪值（ADR-0002）——板块轮动与跷跷板效应意味着同一天不同板块必然处在不同的情绪周期位置，科技高潮时老登股往往正在退潮，一个全市场数值无法表达这种分化，而分化恰恰是本系统要捕捉的东西。

市场层产出的是板块分析与推演的**环境输入**；并非每个字段都直接加减情绪指数：

- **政策环境**：取值为无干预 / 政策暖风 / 国家队托底中 / 政策打压。它不改变推演结构，只通过乘法因子改变各行为的概率分布，不直接加减情绪指数。国家队不是第四方参与者，而是体现为政策环境的取值。
- **流动性环境**：市场整体钱多钱少、增量还是存量。
- **交易环境**：板块轮动节奏、风格偏好、资金抱团方向。
- **情绪广度**：对所有在册板块情绪的横向聚合（处于高潮的板块占比、情绪中位数）。这是派生指标，不是重新计算的市场级情绪。

市场层数据直接复用 DSA: C:\Users\bai\Documents\我的文档\股票\新项目\SecondOrderGame\daily_stock_analysis-main 的大盘分析模块，提取结构化大盘数据 + 盘面 + 指数 + 板块。

### 2.2 板块层

板块层是情绪的归属层。每个板块独立计算情绪指数、独立维护跨日惯性。

**板块列表是动态的**，不取全量（富途行业板块上百个，成本不可接受）。构成规则：自选池所涉板块 + 涨跌幅榜前后各若干板块。前者覆盖持仓，后者覆盖「资金正在流入而你尚未关注」的板块。目标规模 20–30 个板块。

**情绪指数的形成机制**（基准 50，范围 0–100，参考钟摆理论：两极之间变化极快）：

1. 基本面在板块首次建档时给出初始基准值（行业供需、盈利水平、政策框架、竞争格局），不自动按季度重锚（ADR-0023）
2. 结构化消息事件对基准值加减分：先做相关性、有效性、来源可信度、主体目的与事件去重分析
3. 行情面对基准值加减分：只使用规范板块代码对应指数的 OHLCV 计算一日、两日收益，不读取个股通用收益字段
4. 惯性约束：不因单条消息或单日回调而扭转。在大盘板块大幅回调、连续砸盘等重大行情影响下，主力信号已成为最强「消息」，利好新闻影响甚微，情绪仍会降低

**情绪指数与情绪周期位置是两个独立字段。** 指数是连续量（用于观察程度与变化速率），周期位置是离散判断（五档，作为 HMM 隐状态）。不要用阈值从指数机械映射到档位——档位由大模型按结构化提示词判断，再经混淆矩阵折算。

运行时由 `src/data/sentiment_calculator.py` 按 ADR-0014/0023 计算指数，并由 `SentimentLedger` 按规范 `sector_code` 持久化。消息预取后的预分析生成结构化消息事件；行情由统一数据接口读取 `index_source` 对应板块指数日线并计算收益。交易所日历未确认当日开市时保持原值且不写台账。同一交易日固定昨日基准，允许新闻缓存刷新后重算但不会重复累加。指数进入板块分析材料用于展示和审计，但不生成周期候选集，也不参与周期档位判定。

**五档定义**（ADR-0021；ADR-0012 的旧状态划分已被替代）：

| 档位 | 特征 |
|---|---|
| 冰点 | 极度悲观，成交量萎缩，价格长期横盘或下跌 |
| 启动 | 低位反转，趋势尚待确认 |
| 发酵 | 上升趋势已确认，赚钱效应开始扩散（v1 用价格趋势代理） |
| 高潮 | 情绪极度乐观，成交量放大，FOMO 追高普遍 |
| 退潮 | 情绪急转直下，恐慌卖出，筹码换手 |

「分歧」不是情绪周期位置，而是可在任一位置出现的板块级共识状态；共识状态取「一致/分歧」，并以「转强/转弱/未确认」描述演化方向。「侥幸」仍是「退潮期 + 羊群散户未离场」的行为特征描述。「升温 / 降温」并入启动 / 退潮。

### 2.3 个股层

博弈信号、主力行为概率、T+1 闸门、应对树都在个股层。

**隐状态与行为分属两层**：HMM 的隐状态是**板块**情绪周期位置，行为是**个股**主力行为，映射表 `W[z, x]` 即「板块情绪周期 → 个股主力行为」。这与「情绪冰点对应主力建仓试盘」的原始直觉一致，并顺带解决了跨截面池化的对象问题——在同一板块周期位置下池化该状态的所有个股，样本量才够。

## 3. 参与者模型

### 3.1 两方参与者

| 参与者 | 盈利方式 | 周期 | 信号特征 |
|---|---|---|---|
| 主力 | 价格控制与筹码博弈 | 短至长 | 大单（super/big/mid）；短周期者信号可伪造，长周期者难伪装 |
| 散户 | 情绪与从众 | — | 被收割方，同时是反向指标 |

主力包含操纵型（游资、同质化量化，周期短，单日成交量突兀）与配置型（价值型机构、长线外资，周期长，建仓缓慢）。两者在单日资金流上均表现为大单，无法从净额区分，因此在 W 矩阵中合并为一个参与者类。序列特征（如连续五日小单吸筹 + 无拉升）可以在观测层作为配置型主力的额外证据，但不拆分 W 的参与者维度（见 ADR-0018）。

A 股无正式做市商制度，参与者枚举中不存在做市商。国家队不是参与者，是改变推演环境的外部力量（体现为政策环境取值）。

### 3.2 参与者各自的六种行为

主力行为枚举（个股事后标注器与主力 W 行共用）：

```
建仓 | 震仓 | 拉升 | 出货 | 观望 | 狩猎止损
```

散户行为枚举（散户 W 行与散户提示词路由共用）：

```
FOMO追高 | 恐慌割肉 | 观望 | 理性跟随 | 底部建仓 | 高位减仓
```

主力标签描述筹码与价格控制，散户标签描述情绪与跟随反应。两者只共享「观望」，配置校验、HMM 输出 schema 与参数工作台必须按参与者选取词表，不能共用一套列名。

### 3.3 信号可信度：分离与混同

**分离均衡信号**：主力无法伪装的高成本信号。可信度 = 信号成本 / 信号收益。业绩超预期叠加机构入驻属此类。

**混同均衡信号**：主力可低成本伪造、无法区分真实意图。单日涨停、模糊利好属此类。

推演时必须区分两者——把混同信号当分离信号采信，正是主力收割的入口。

## 4. 概率架构：三类概率，三种命运

**这是本设计最关键的分层，也是最大的陷阱所在。** 把三类概率当成同一个难题会导致整个系统在 Day 0 无法启动。

| 类型 | 内容 | 是否含隐状态 | 是否需标签 | Day 0 可用 | 来源 |
|---|---|---|---|---|---|
| **A** | 主力行为概率 | 是 | 是 | ❌ 仅专家先验 | HMM 前向滤波 + 手写三表 |
| **B** | 开盘区间 / 下一根 K 线分布 | 否 | 否 | ✅ | 价格历史经验估计 |
| **C** | T+1 首次触及概率 | 否 | 否 | ✅ | 分层日块 bootstrap |

A 类在 Day 0 只有专家先验，UI 必须醒目标注「专家先验推演，非统计估计」。B、C 类从第一天起就是真正的统计估计，可以直接支撑 T+1 闸门。

### 4.1 A 类：HMM 前向滤波

三张手写表，全部在 `config/hmm_prior.yaml`：

- **A（转移矩阵）** 5×5：`A[from][to]` = 本 K 线处于 from 档位时，下根 K 线转移到 to 档位的先验概率
- **C（混淆矩阵）** 5×5：`C[true_z][llm_ℓ]` = 真实档位为 z 时，大模型输出标签 ℓ 的概率。**大模型是噪声传感器**，其情绪判断不被直接采信，而是经此矩阵折算为对隐状态的观测证据
- **W（行为映射）** 5×2×6：`W[z][participant][behavior]` = 板块情绪处于 z 时，该参与者执行该参与者词表中某个行为的概率。参与者维度为 2（主力/散户），两行分别使用 §3.2 的主力/散户词表，见 ADR-0018。

**前向滤波**（每根 K_120M 收盘时执行，约十行代码）：

```
预测步：b_pred(z) = Σ_z' b_{t-1}(z') × A[z' → z]
更新步：b_t(z)   ∝ C[z][llm_ℓ_t] × b_pred(z)     再归一化
```

**行为预测**：

```
P(behavior) = Σ_z b_t(z) × W_eff[z, participant, behavior]
```

**政策修正**（乘法，逐行乘完后重新归一化，不改变概率的相对结构）：

```
W_eff[z, p, b] = W[z, p, b] × policy_multipliers[p][policy][b]
```

**先验强度**：每行携带 `alpha`（Dirichlet 先验强度 / 等效样本量），由口头信心反推：

```
α₀ = m(1-m)/sd² − 1
「大概 55%，可能偏 10 个点」→ ESS ≈ 24
「大概 55%，可能偏 20 个点」→ ESS ≈ 5
```

α 下限 0.3，否则单次意外无法撼动后验。

**先验权重**必须随每个 A 类概率输出一并返回，使审计者看得见数据何时开始接管先验。

**先验向数据过渡（后验融合，ADR-0029）**：`hmm_prior.yaml` 的 C/W 是手写先验；事后标注器积累的标签经 `ConfusionCountStore`（C）与 `BehaviorCountStore`（W）计数，由 `src/labeler/calibration.py::load_production_hmm_config()` 融合为后验矩阵——`后验 = (alpha·先验 + 计数)/(alpha + n)`，逐行归一化。生产链 `production_context` / `production_orchestrator` 消费融合后的 config；空库时回退纯先验（零回归）。散户 W 行因散户层标注器未实现暂保持先验（ADR-0018）。

### 4.2 B 类：下一完整 K 线时段分布

**必须维护两套独立的经验分布**（ADR-0003 / ADR-0030）：

- `intraday_next_bar`：午盘决策使用，观测下午收盘相对上午收盘的完整时段收益
- `overnight_next_bar`：收盘决策使用，观测次日上午收盘相对当日下午收盘的完整时段收益，包含隔夜跳空与次日上午走势

跳空与非跳空是两种物理机制，不应混在一个分布里靠标志位区分。不得把午盘 B 类退化为「下午开盘相对上午收盘」的午休跳变；A 股午休前后价格高度连续，会导致「符合预期」概率虚假集中到接近 100%。既有 `OpeningDistribution*` 类型名与 `gap_down / near_reference / gap_up` outcome 是兼容标识，生产语义以本节的完整时段定义为准。

### 4.3 C 类：T+1 首次触及概率

分层日块 bootstrap 估计。**条件单元**由波动率分位 × 近期收益 × 换手率分位 × 情绪周期位置界定。

样本量低于阈值时：先降维重算（减少条件维度），仍不足则返回「数据不足」并将对应 T+1 闸门判为不通过。

### 4.4 校准

**校准度是唯一能反向修正先验的评分指标**，优先级高于方向准确率，方向准确率高于交易结果。

理由：交易结果混杂了执行、仓位、运气，无法定位模型错在哪里；方向准确率忽略了概率幅度（把 51% 说成 95% 也算对）；只有 Brier score 这类校准指标能告诉你「你说 70% 的那批事件，实际发生了多少」。

预测数量未达阈值时拒绝输出校准分数，不显示一个基于 5 个样本的 Brier score。

## 5. 时间架构：双决策点与 K 线周期

### 5.1 两个决策点

| 决策点 | 可执行动作 | 「下一根 K 线」语义 |
|---|---|---|
| 午盘 11:30 | 卖出旧仓（下午立即执行）+ 规划下午买入（次日解锁） | 今天下午，**无跳空** |
| 收盘 15:00 | 规划次日买入 + 规划次日卖出旧仓 | 明天上午，**有跳空** |

**午盘决策点的核心价值是降低 T+1 风险，不是副作用**（ADR-0003）。午盘入场把 T+1 锁定期的隔夜暴露窗口从「4 小时盘中 + 1 次跳空」缩短为「2 小时盘中 + 1 次跳空」。

**持仓状态必须携带建仓时间戳**，不能只记数量。午盘买入的仓位在当天收盘决策时是「今日新仓」不可卖，次日才解锁。同一品种可能同时存在可卖旧仓与不可卖新仓，不能用单一布尔值表示是否可卖。

**可执行动作集合由程序按 T+1 规则与持仓账龄计算**，作为结构化字段注入提示词，不由大模型判断。制度是事实，不是判断。

两个决策点共用同一个 JSON schema，以 `decision_point` 字段区分，差异通过程序计算的 `executable_actions` 字段表达，不开两套 schema。

### 5.2 K 线周期

固定使用 `K_120M`（ADR-0004）。

`K_240M` 在 A 股因午间休市实际返回两根 K 线，与 `K_120M` 结果相同，但富途官方文档对这一分段行为**没有任何说明**——它是未文档化的行为，任何一次 OpenD 更新均可在不破坏兼容性的情况下改变它。

`K_120M` 语义明确（120 分钟就是 120 分钟），且与双决策点天然对齐：每个决策点恰好对应一根已收盘的 `K_120M`。

此决策仅针对 A 股。扩展至美股时需重新评估（美股无午间休市，`K_240M` 是真正的连续 240 分钟）。

## 6. 数据层

### 6.1 数据源

| 数据 | 来源 | 约束 |
|---|---|---|
| 行情（K 线、盘口、板块） | 富途 OpenAPI | 免费齐全快速，K_120M |
| 资讯搜索 | 富途 `get_search_news` | **限频 10 次 / 30 秒** |
| 补充资讯 | Tavily API | 富途无法覆盖时降级使用 |
| 龙虎榜 | AkShare | P4 阶段接入 |

**不接入**：北向资金、申万行业分类（评估后判定收益不足以抵偿复杂度）。

### 6.2 消息后台预取

消息搜索**不能在决策触发时同步拉取**（ADR-0006）。20–30 个板块在 10 次/30 秒的限频下需要 60–90 秒，会严重阻塞午盘决策点。

因此消息搜索作为后台任务在盘中持续运行：每 3 秒搜一个板块，结果写入当日分析材料缓存。决策时直接读缓存，零额外延迟。

**消息与个股的关联**不依赖反查。用户注册个股到自选池时同时填写对应板块名称；后续搜板块名，利用返回结果的 `related_securities` 字段确认关联。关联关系在入池时由用户显式维护。

### 6.3 落盘策略

**分析流水线全程驻内存，收盘一次性序列化落盘**（ADR-0008）。富途接口返回的 JSON 以字符串 / 字典形式驻留内存，各环节直接使用；本地文件写入是终点动作——整条分析记录一次性序列化保存，中间没有任何「写文件 → 读文件」环节。

**两个例外**（因为必须跨进程重启存活）：

1. **情绪台账**：每板块每日的情绪指数与周期位置。情绪有惯性，今日值以昨日值为基准加减，进程重启不能丢失。它是一等公民的领域状态，不是分析记录的副产品。SQLite 持久化。
2. **分析材料缓存**：日级共享状态，盘中多次分析（多个个股、两个决策点）共享同一份，节省重复 API 配额与延迟。写入只发生在后台填充阶段，读取发生在决策阶段，两者严格隔离。当日有效，收盘归档，次日重建。

### 6.4 事后标注器

HMM 的数据驱动更新依赖标签，但情绪周期位置与主力行为都是隐状态，运行时无法直接观测，只能事后从价格数据推断。

**两个独立标注器，各自独立冻结、独立哈希**（ADR-0007）：

| 标注器 | 输入 | 输出标签 | 状态 |
|---|---|---|---|
| 板块层 | 板块指数 OHLCV | 冰点 / 启动 / 发酵 / 高潮 / 退潮 | v1 已冻结；v2 影子运行中 |
| 个股主力层 | 个股 OHLCV | 建仓 / 震仓 / 拉升 / 出货 / 观望 / 狩猎止损 | 已冻结（ADR-0017） |
| 个股散户层 | 个股 OHLCV + 散单/情绪证据 | FOMO追高 / 恐慌割肉 / 观望 / 理性跟随 / 底部建仓 / 高位减仓 | 设计草案，未实现 |

板块层另保留与五档周期正交的结构事件：无、平台整理、二次启动、加速、高位兑现、破位转弱。事件不是 HMM 隐状态；高潮后平台未破时周期位置回到发酵，向上突破记录二次启动，向下破位且板块强度和赚钱效应扩散转弱时才进入退潮（ADR-0022）。

每晚用前视窗口（t…t+5）扫描历史，产生延迟 5 日的标签流。

**必须 Day 0 上线，不能等系统「稳定了再说」。** 每一天不跑就是永久损失一天的标签，而标签是让先验向数据过渡的唯一燃料——启动越晚，冷启动期越长。

**标注器是定义，不是真相。** 它把抽象概念（「出货」）映射成可程序验证的条件（例如「高换手 + 未创新高 + 3 日前向收益为负」），这个映射是人为选择。一旦冻结，不能为了让准确率好看而修改；改动会作废此前累积的全部计数。真正应做的是在 ADR 记录更改原因并重算历史标签。

修改个股标注规则不会作废板块层已积累的计数，反之亦然——这是「独立哈希」的价值。

### 6.4.1 生产接入（夜间调度 + 启动自动补跑）

标注器经 `src/labeler/nightly.py` 接入生产链，CLI 入口 `secondordergame-labeler-nightly`，每晚一次：

1. **标签流落库**（ADR-0007 Day 0）：板块 v1 与个股主力层标签写入 `runtime/labeler/labels.db`（`LabelLedger`，按 scope/entity/日期/rule_hash 幂等 upsert），延迟窗口内的未来日期一律不写。
2. **板块 v2 影子运行**：`SectorLabelerV2` 产出的成分股扩散标签写入 `runtime/labeler/shadow_v2.db`（`ShadowStateStore`），满足「每板块 5 个合格日 + 连续 3 日无结构性错误」门槛后，`ShadowCutoverManager` 全量重标、独立重建 C 计数并原子切换 `runtime/labeler/production/active.json`。v2 阈值尚未人工验收（ADR-0022），数据不足时安全不切流。
3. **C 混淆矩阵回灌**：生产链每次 LLM 周期观测（`ProductionOrchestrator._observe_cycle`）经 `llm_observation_sink` 写入 `runtime/labeler/confusion.db`（`ConfusionCountStore`）；夜间调度将板块真实标签与同日 LLM 观测配对，累加 `C[true_z][llm_ℓ]`，供 HMM 后验校准。

**启动自动补跑**：`PAEmbeddedService` 初始化时在后台 daemon 线程执行 `run_labeler_catchup`——查询 `LabelLedger` 各板块最新标注日，落后于补跑窗口（`CATCHUP_LABEL_WINDOW` = 前视 10 + 5 + 3 缓冲 = 18 交易日）的板块，逐日补跑 `run_nightly`。该机制保证即使某晚漏跑，下一次打开程序也会自动补齐，守住 ADR-0007「每一天不跑就是永久损失一天标签」。板块列表默认读 material_cache 的 `sector_registry`，可注入 `labeler_catchup_sectors`；数据源不可用时提示并跳过，不阻塞程序打开；重复打开幂等（已补齐的板块零网络开销）。

**自选池模式（个股标注范围简化）**：程序无法可靠判断个股是否属于在册板块（成分股关系不可用），因此个股标注范围直接以**自选池**为权威——`run_nightly(..., watchlist=...)` 时，每个自选标的用其**关联板块指数**（PA 二阶设置 `symbol_preferences`，`load_pa_settings_mapping` 读取并过滤脏值）做超额收益基准，资金流从 P0-8 ledger 注入做「主力/散户」判定；未配置关联板块的标的本轮跳过并记录 `sector_mapping_missing`。关联板块指数同时产板块 v1/v2 标签与 C 计数，板块层范围随之收敛为自选池的关联板块。CLI 用 `--pa-settings <settings.json>` 进入该模式；`PAEmbeddedService` 配置 `pa_settings_path` 后启动补跑即走自选池模式。

数据源：富途 OpenD（`FutuMarketDataSource`），板块 K_DAY 走统一板块行情源，个股 K_DAY 走订阅源。单板块失败不中断整夜调度；v2 观测数据源与 TrendState 规则当前为可注入、可降级设计，缺数据时仅记录原因不产出标签。

## 7. 博弈信号（程序计算）

所有博弈信号由 Python 按固定公式从价格与成交量计算，**大模型不参与数值生成**（ADR-0009）。参数来自配置文件，不硬编码。

**纳什均衡带**：以短周期均值为中心、以标准差乘偏差率为半径的价格区间，代表参与者集体预期的锚点。价格在带内为均衡，带外为某一方暂时占优。

**逆势信号**（反向博弈核心）：
```
逆势买入 = 羊群卖出 AND 吸筹
逆势卖出 = 羊群买入 AND (派发 OR 上方流动性陷阱)
```
下方流动性陷阱已从逆势买入移除（ADR-0026）：它在 A 股实测为破位下跌延续（看跌），不再是看涨条件。

**动量信号**（跟随强者）：
```
动量买入 = 价格在带下方 AND 聪明钱指数为正 AND NOT 羊群买入
动量卖出 = 价格在带上方 AND NOT 聪明钱指数为正 AND NOT 羊群卖出
```

**纳什均衡回归信号**：
```
回归买入 = 价格在带下方 AND 当根收 > 前根收 AND 量 > 均量
回归卖出 = 价格在带上方 AND 当根收 < 前根收 AND 量 > 均量
```

**支撑概念**：

- **羊群行为**：技术指标极值、成交量异常、动量偏离三者同时成立的群体一致行动。同质化量化策略也会形成羊群行为。
- **流动性陷阱**：突破技术位或心理价位后快速回撤、伴随异常成交量的价格形态。分上方与下方：上方陷阱是向上假突破后回落（看跌）；下方陷阱在 A 股实测为破位下跌延续（看跌，ADR-0026），而非文档的「猎杀止损后反弹」。与「假突破」的区别：假突破是形态，流动性陷阱是意图。
- **止损狩猎**：主力探测止损密集区 → 驱动价格触发止损 → 在下方接收恐慌筹码的三阶段行为。是主力行为标签（事后标注器用前视反弹判定，看涨），与下方流动性陷阱（实时观测特征，看跌）分属不同命名空间。
- **聪明钱指数**：衡量单根 K 线内资金净效果的程序指标。它是信号名，不指代任何参与者。

⚠ **「吸筹」「派发」在这里是信号名，不是行为标签。** 它们由 AD 线与机构成交量算出（`accumulation = ad > ad_ma AND institutional_volume`），是实时可观测的量价特征。行为标签「建仓」「出货」是事后标注器用前视五日窗口判定的隐状态，两者同名概念但不同命名空间，取值也不会一一对应——一根 K 线可以有 `accumulation` 信号却被标注成「震仓」。实现时不要把信号名当标签用，也不要用信号直接推标签。

**信号在本项目是观测特征，不是交易信号**（ADR-0016 六）。参考文档把上述三类信号直接当买卖点用并配了仓位管理，本项目都不采用：信号喂给大模型做周期位置判断与行为推断，仓位归 PA_Agent。所以不合成综合买卖信号，也不需要信号冲突仲裁与冷却期。

大模型可以**解释**信号（「当前均衡带下方逆势买入，因为成交量异常叠加聪明钱净流入」），但信号以已计算完毕的结构化字段注入提示词，大模型只读不写。

K 线图使用独立的博弈信号时间序列：对最近 20 根已收盘 `K_120M` 逐根计算，每个点只读取该点及此前数据。该序列只服务于纳什均衡带和信号标记的图表叠加，不进入大模型；界面结论与大模型输入仍只使用最新一根已收盘 K 线的单点快照。为完整生成 20 个可用点，行情层至少准备 48 根 K 线（29 根指标最低窗口 + 19 根绘图回放窗口）。

**参数出处**：全部在 `config/signals.yaml`（ADR-0016）。这些值来自加密市场日线的优化结果，周期已按 K_120M ×2 换算，本质是专家先验起点而非本市场验证值——与 `hmm_prior.yaml` 的 alpha 同性质，输出需挂「专家先验推演，非统计估计」。文档未给数值的参数（流动性陷阱的回撤幅度、羊群的动量偏离幅度）在配置里保持 `null`，触发条件即纯布尔判定，不得填入自造数值。

**可视化**：信号绘制在 K 线图表中。背景色编码博弈状态（羊群买入警示红、羊群卖出机会绿、聪明钱活跃蓝）；三角标记逆势时点，十字标记流动性陷阱位置。可视化是呈现，不影响计算。

## 8. 推演引擎

### 8.1 流程

```
① 读取分析材料缓存
   （消息事件、主体目的、大盘行情、板块情绪、个股博弈信号）
        ↓
② 参与者识别
   注入「参与者识别」提示词 → 大模型输出结构化 JSON
   → 把当前行为归类到三方参与者
   → 产出「当前参与者行为待选列表」
        ↓
③ 提示词路由（纯函数）
   按 (情绪周期位置, 参与者类型) 查 config/prompt_routing.yaml
   → 返回对应推演思路 txt 路径
        ↓
④ 主力行为推演
   注入路由到的推演思路 + 人设与思维方式提示词
   → 大模型输出未来行为的离散标签
   → 程序过滤不可能事件
   → HMM 信念加权得到 A 类概率
        ↓
⑤ 应对树生成
   三情景 × 参与者行为矩阵
   每叶节点：概率 + 行动建议 + T+1 闸门结果
```

### 8.2 提示词路由是纯函数，映射表是配置

路由必须是无副作用纯函数（ADR-0005）——大模型无权自行决定读哪些提示词文件，那会让路由不可复现、不可测试，且大模型可能要求不存在的文件。

但映射表放配置文件而非硬编码，因为「哪种情绪周期位置配哪套推演提示词」是随经验积累而调整的配置，写死在代码里意味着每次调优都要改代码、走测试、重部署。

两者正交：纯函数的约束是「查表返回已知文件、无副作用」，不是「表必须写在代码里」。

程序在加载时校验所有路径存在，大模型运行时拿不到超出合法集合的文件名。配置文件版本号随每次分析记录一并保存。

### 8.3 提示词目录结构

```
prompt_engine/
  主力/         建仓.txt 震仓.txt 拉升.txt 出货.txt 观望.txt 狩猎止损.txt
  散户/         FOMO追高.txt 恐慌割肉.txt 观望.txt 理性跟随.txt 底部建仓.txt 高位减仓.txt
  通用/
    参与者识别.txt
    人设与思维方式.txt
    主体目的分析.txt
    情绪周期判断.txt
```

使用手册必须列出所有提示词路径（ADR-0011）。每新增文件同步更新 `config/prompt_routing.yaml` 与使用手册。

### 8.4 推演的核心方法：序贯理性

站在主力视角预判散户反应，再据此预判主力的下一步。推演不追求猜对单一结果，而是**尽可能多地覆盖可能出现的情景**，方便系统制定针对性方案。

行为路径示例（不穷举，实际由提示词与 W 矩阵共同决定）：

```
冰点（极度恐惧）  → 建仓 / 震仓（低吸收集筹码）
启动或发酵（趋势转强） → 震仓 / 拉升（换手后观察是否转强一致）
高潮（极度贪婪）  → 出货 / 拉升（利用一致性追涨兑现）
退潮（恐慌踩踏）  → 出货 / 狩猎止损（顺势收割，等待下一冰点）
```

板块级「分歧」作为正交共识字段参与解释：分歧转强一致偏向继续上涨，分歧转弱一致偏向撤退；它不进入 HMM 的五个周期隐状态。

**共识的诅咒**是二阶思维的核心依据：信号成为市场共识后不仅失效，反而成为反向收割工具。推演时必须问「这个信号已经多少人看见了」。

### 8.5 政策环境感知

- **硬信号**：沪深 300 / 上证 50 ETF 异常放量（汇金惯用通道），国家队托底或政策指导龙头信号。当日成交量 ≥ 历史中位数 × `abnormal_volume_ratio`，且满足条件的 ETF 数量 ≥ `minimum_confirmations` 时，硬信号成立 → 政策环境 = 国家队托底中。
- **软信号**：直接扫描各板块原始新闻缓存（`news` 类别）的 title + snippet 文本，匹配业务词表（政策 / 国家 / 政府 / 中央 / 降准 / 降息 / 稳市场 / 降税 / 释放流动性 / 提振信心 / 增量资金 / 稳增长 等）。业务词写广写全，A 股政策环境以暖风为主，宁可多命中也不漏判；「政策打压」在 A 股基本不存在，词表仅保留极少量词维持四环境结构。
- 输出结果决定 `policy_multipliers` 选用哪一组因子。政策环境**不改变推演结构**，只改变概率分布——这是它与「状态重置信号」的关键区别，后者暗示要走另一条推演路径。
- 检测参数全部在 `config/policy_detector.yaml`（ETF 清单、放量阈值、确认数、业务词表），由 `src/reasoning/policy_detector.py` 确定性执行，大模型不参与数值生成。生产链路中 `ProductionContextBuilder` 在构建 `BridgeContext` 时运行检测，产出环境与证据链注入决策材料供审计。

## 9. PA 联动

### 9.1 两种模式

| 模式 | 下单依据 | 二阶博弈角色 |
|---|---|---|
| T+0 | 技术分析模块决策 | 可独立查看，不阻塞交易 |
| T+1 | 二阶博弈结论 | PA 阶段 2 决定下单后自动触发；不下单则不触发 |

### 9.2 T+1 联动流程

```
PA 阶段 1 → PA 阶段 2 完成 → 是否下单？
        ├─ 否：结束联动，不运行二阶博弈
        └─ 是：on_stage2_complete 回调触发（不需用户手动操作）
                ↓
二阶博弈完整推演
        ↓
PA 阶段 2 的 JSON 输出路由到二阶博弈大模型输入
+ 注入系统提示词（要求给出技术分析下单可行性 + 全情景应对树）
        ↓
二阶博弈输出独立布尔闸门 + 理由文本
        ↓
T+1 模式下作为下单前最后一道判断
```

**为什么不是「调整胜率」**：PA 的 `estimated_win_rate`（0–100，可为 null）只用于**显示**，下单闸门在 `util/trade_metrics.py`，只看盈亏比（`MIN_RISK_REWARD_RATIO = 1.0`，上限 `MAX_TP1_RISK_REWARD_RATIO = 1.0` 且超限时调宽止损而非缩小目标）。胜率不参与任何计算，改它不影响下单。

因此二阶博弈输出的是独立闸门，不改 PA 的盈亏比逻辑。这样两个系统的下单逻辑不纠缠，PA 可以单独升级。

**触发机制**：在 `TwoStageOrchestrator` 加可选的 `on_stage2_complete` 回调参数，并在回调边界同时校验 `settlement_mode == "t1"` 与 PA 阶段 2 的 `should_trade == true`。不借用它已有的 `router` 注入点（该参数支持传对象），因为路由必须是无副作用纯函数（ADR-0005），且 `.route()` 在阶段 1 之后调用，不是阶段 2 完成的时机。T+0 模式或 PA 决定不下单时均不运行二阶博弈，仅同步阶段 2 结果供用户独立查看。

**最终下单与否由程序化闸门决定，不由大模型直接输出「买 / 不买」。**

**读取 PA 输出时的注意**：阶段 2 schema 有 conditional required——不下单时 `entry_price` / `stop_loss_price` / `estimated_win_rate` 必须为 null，下单时必须有值。必须处理 null 分支。

### 9.3 UI 位置：品种页内第三层子标签栏

PA 现有两层 QTabWidget：**工作区层**（自选股 + 每个品种一页）和**分析侧栏层**（历史记录 / 交互 / 决策 / 未来走势预期 / 决策树 / 决策树可视化 / 原始 / 调试）。

二阶博弈不进这两层任何一层，而是在品种页内部新建**第三层**子标签栏：打开一个品种后，页面内有一个子标签栏，把「PA 技术分析流程」与「二阶博弈流程」并列为两个独立工作区。这个子标签栏在视觉上须与工作区那层明确区分，避免层级混淆。

理由：两个流程各自完整、可独立使用。放进分析侧栏会让二阶博弈降格为 PA 分析流程的一个视图，而它是平级的分析体系，有自己的完整流程（消息预取 → 情绪判定 → 参与者识别 → 推演 → 应对树）。放进工作区层则与「品种」概念冲突——二阶博弈是对某个品种的分析，不是另一个品种。

用户可选择独立运行，或在技术分析模块中开启 T+1 模式自动联动。详见 ADR-0015。

### 9.4 重复逻辑的处理

两个系统在部分逻辑上重叠（PA 的价格行为学也识别假突破）。处理原则：**PA 判形态，二阶博弈判意图**。同一个假突破，PA 负责确认它在技术上成立，二阶博弈负责回答「谁制造的、为什么、下一步会怎样」。不去消除重叠，而是明确各自的输出边界。

## 10. 情景应对树

系统的最终产物。**不是对单一走势的预测，而是覆盖可能空间的策略矩阵。**

### 10.1 三情景

| 情景 | 特征 |
|---|---|
| 超预期强 | 开盘爆买 / 大幅高开 |
| 符合预期 | 平开 / 微幅高开，板块按部就班 |
| 低于预期 | 大幅低开 / 核心标的被砸 |

### 10.2 每情景包含

- 各参与者最可能的行为及其概率（A 类，携带先验权重）
- 开盘区间分布（B 类）
- 首次触及止损 / 目标位的概率（C 类）
- 板块轮动中的应对
- 收益与风险平衡后的行动建议
- T+1 闸门判断（通过 / 不通过 / 数据不足）

### 10.3 假设验证

系统运行一段时间后，用历史上概率最大决策的实际结果对比预测，计算校准度并回测板块走势，产出系统级打分与原因说明。

**属离线评估流程，不在实时决策路径上运行。** 它的产物是「先验该往哪个方向修正」，而不是实时的置信度调整。

## 11. 配置与版本化

### 11.1 全局要求

**不得在代码或架构文档中硬编码博弈论参数。** 所有阈值、参数、乘数、评分通过配置文件注入，支持动态加载。

### 11.2 配置文件清单

| 文件 | 内容 |
|---|---|
| `config/hmm_prior.yaml` | A / C / W 三表 + 政策乘数 + 初始信念 |
| `config/prompt_routing.yaml` | (情绪周期位置, 参与者类型) → 提示词路径 |
| `config/signals.yaml` | 纳什均衡带周期与偏差率、羊群行为阈值等 |
| `config/sectors.yaml` | 板块列表构成规则、自选池与板块对应关系 |

### 11.3 版本化规则

1. 修改任意配置数值前，先递增该文件的 `version`
2. 每条分析记录保存当时使用的所有配置版本号
3. 修改配置 = 使历史先验权重失去可比性（这是正常代价，不是 bug）

### 11.4 启动时校验

`src/config_validator.py` 在每次启动时运行，校验：

- 顶层键完整性
- 状态名 / 参与者名 / 行为名拼写（多余键与缺失键都报错）
- 概率非负、每行和为 1.0 ± 0.001
- `alpha` ≥ 0.3
- 混淆矩阵 `llm_` 前缀格式
- 政策乘数非负

**校验失败拒绝启动，不静默降级。** 错误消息包含完整路径与具体问题，不需要调试器。

## 14. 未决事项

以下事项已识别但尚未决策，需在对应阶段开工前确认：

1. **板块层标注器的五档情绪判定规则**。个股层已冻结（ADR-0017，六种行为的阈值来自 94,594 个股票日的实测）；板块层 v1 规则已形成 OHLCV 草案，冻结验证见 T08，五档为冰点/启动/发酵/高潮/退潮。分歧作为正交的板块共识字段，平台整理/二次启动等作为正交事件字段；两者待 v2 成分股数据支持后量化。

   ⚠ 这一项有一个额外约束：判定必须直接从板块指数 OHLCV 出发，**不能拿情绪指数做阈值映射**。情绪指数是解释性数值，可注入大模型作为辅助参考，但若用它做阈值映射推导周期状态，混淆矩阵 C 就会退化成恒等映射，整个"大模型是噪声传感器"的设计随之失效。

2. **提示词生产接入**。`prompt_engine/` 的通用与两方行为提示词已完成（T21/T22），并统一输出五档周期及正交事件；生产路由、结构化校验和模型调用接入由后续工单负责。

3. **多板块归属**。当前一只股票只有单一主板块，跨行业业务的标的无法表达。个股标注器的相对收益基准依赖主板块，改成多归属需要独立 ADR，不能在标注规则里临时混合基准。

4. **异常交易日历**。涨跌停与除权日目前保留真实价格行为，没有单独标记。`signals.yaml` 的 `degenerate_bar` 只封了 `high == low` 这一种退化（一字板），未覆盖除权跳空。

## 15. 交给开发者时的注意事项

**可以直接开工的部分**：P0 全部（P0-5 个股标注器的规则已冻结在 `config/labeler.yaml`）、P1 全部、P2 的 P2-1 / P2-2 / P2-3、P3 全部（接入点见 ADR-0015）、P5 全部。这些任务的架构合约（数据结构、接口、约束）已经明确。

**需要先补决策的部分**：P0-4 板块层标注器依赖五档情绪判定规则；P2-4 / P2-5 / P2-6 的提示词内容已完成，剩余生产路由、结构化校验和模型接入。

**最容易犯的五个错误**：

1. **把三类概率当成一个问题**。看到「Day 0 没有标签」就以为整个概率引擎都要等数据，于是推迟 P1。实际上 B、C 类从第一天就能跑，且它们才是直接支撑 T+1 闸门的部分。
2. **让大模型输出数字**。任何「让 AI 估一下概率」的实现都违反 ADR-0001，且不可复现、不可审计。大模型只输出固定词表内的标签。
3. **推迟标注器**。「先把主流程跑通，标注器后面加」是最贵的错误——每延迟一天就永久损失一天标签。标注器必须在 P0 完成。
4. **把无标签日兜底成「观望」**。看到 73% 的交易日没有标签会本能地想找个默认值填上。实测证明这会让观望从 19,401 行涨到 88,459 行（4.56 倍），把「主力主动不动」和「规则不知道」混成一列，观望这一列的解释力直接归零。校验器会拦住配置层面的开关，但如果在代码里硬写兜底，校验器拦不住。见 ADR-0017 五。
5. **把参考文档的周期数字直接当 K 线根数用**。`signals.yaml` 里所有周期都已按 K_120M ×2 换算过（RSI 28 而非 14，纳什 8 而非 4）。参考文档的单位是交易日。校验器的整除检查只能抓奇数，抓不住「文档原值恰好是偶数」的情况（14 就是），所以这一条需要人工比对 ADR-0016 一 的换算表。
