# W 矩阵从三方参与者压缩为二方，与测量层对齐

## 问题

原始设计将 W 矩阵定义为 `W[z][participant][behavior]` = 5×3×6，三个参与者为操纵型主力、配置型主力、羊群散户。但测量层与推演层在参与者数量上存在结构性不对齐：

1. **单日资金流无法区分两类主力**。富途 `get_capital_flow` 返回的 super/big/mid/small 分档只能区分「主力」（大单）vs「散户」（小单），无法从单日净额判断是操纵型还是配置型——两者都用大单，行为特征的区分需要序列模式（持续吸筹 vs 拉高派发）或龙虎榜数据（覆盖率 1–2%）。

2. **样本量被三等分**。242 天滚动窗口 × 60 股票 × 27% 覆盖率 ÷ 90 格子 = 每格约 43 个样本，其中狩猎止损（0.2% 占比）的格子只有约 2 个样本 / 15 格。三方拆分使单格样本量低于 Dirichlet 更新的最低有效阈值。

3. **第三行永久先验**。无法从数据校准配置型主力行为概率，第三行只能标注为「永久先验，直至找到归属通道」，这与「数据驱动更新」的设计初衷矛盾。

## 用户的架构澄清

> "我觉得其实并不需要非常细致地去区分操纵型和配置型。因为我在项目架构里也说了，实际上就是散户羊群 VS 一个合并的主力，区分不太开也没有关系。"（2026-08-10）

`ARCHITECTURE.md` §1.2 确实表述为「两个结构性盲区」（看不见参与者 + 看不见共识的诅咒），而非「三方博弈」。三参与者设计是在 §3.1 引入的建模细化，但现在证明这一细化超出了测量层的能力边界。

## 决策

**将 W 矩阵从 5×3×6 压缩为 5×2×6**，合并操纵型主力与配置型主力为单一「主力」参与者类。

新结构：
- 5 个板块情绪周期位置（冰点 / 启动 / 发酵 / 高潮 / 退潮；ADR-0021）
- **2 个参与者（主力 / 散户）**
- 每个参与者 6 种行为：主力使用建仓 / 震仓 / 拉升 / 出货 / 观望 / 狩猎止损；散户使用 FOMO追高 / 恐慌割肉 / 观望 / 理性跟随 / 底部建仓 / 高位减仓

两个参与者的 W 行尺寸相同但词表不同。散户行为描述情绪与跟随反应，不能复用主力的筹码控制术语。

## 影响

### 正面

1. **测量层对齐**。富途资金流的 2 类（主力 vs 散户）可以直接映射到 W 的参与者维度，无需额外归因研究。

2. **样本量翻倍**。每格从约 43 个样本提升到约 86 个，使 Dirichlet 后验更新在冷启动后更快收敛。狩猎止损格子从约 2 个 / 15 格提升到约 4 个 / 10 格。

3. **消除永久先验行**。所有 W 行都可以从资金流 + 行为标签数据校准，不再有结构性不可更新部分。

4. **简化提示词**。`prompt_engine/` 下的参与者目录从三个减为两个，推演路由表 `config/prompt_routing.yaml` 相应简化。

### 负面与缓解

**损失细粒度区分能力**。操纵型（短周期收割）与配置型（长周期持仓）的行为模式差异被抹平。

**缓解**：
- 区分能力本就未实现——原设计的第三行是永久先验，从未从数据中学习过两类主力的差异。
- 序列特征（如「连续五日小单吸筹 + 无拉升」判定配置型）可以在 P4 龙虎榜接入后作为单独的观测证据注入信念更新，而不必拆分 W 矩阵。
- 用户明确表示「区分不太开也没有关系」，这是架构权衡而非能力妥协。

## 迁移路径

### 1. 重写 `config/hmm_prior.yaml` 的 W 部分

原 W 每个状态有三行（操纵型 / 配置型 / 散户），合并为两行（主力 / 散户）。合并策略：

- **如果两行 alpha 相近**（差异 < 20%）：简单平均概率，alpha 取两者均值
- **如果一行 alpha 显著高于另一行**：以高 alpha 行为主，低 alpha 行作 10% 权重修正
- **合并后重新归一化**，确保新行的概率和为 1.0

示例（冰点状态）：

原配置：
```yaml
冰点:
  操纵型主力:
    probs: [0.40, 0.30, 0.05, 0.05, 0.15, 0.05]
    alpha: [9.6, 7.2, 1.2, 1.2, 3.6, 1.2]
  配置型主力:
    probs: [0.30, 0.20, 0.05, 0.05, 0.35, 0.05]
    alpha: [3.0, 2.0, 0.5, 0.5, 3.5, 0.5]
  散户:  # FOMO追高 / 恐慌割肉 / 观望 / 理性跟随 / 底部建仓 / 高位减仓
    probs: [0.00, 0.55, 0.30, 0.00, 0.10, 0.05]
    alpha: [1.0, 1.0, 1.0, 1.0, 15.0, 1.0]
```

新配置（操纵型 ESS=24, 配置型 ESS=10，前者权重 0.71）：
```yaml
冰点:
  主力:
    probs: [0.37, 0.27, 0.05, 0.05, 0.21, 0.05]
    alpha: [7.0, 5.1, 0.95, 0.95, 3.95, 0.95]
  散户:  # FOMO追高 / 恐慌割肉 / 观望 / 理性跟随 / 底部建仓 / 高位减仓
    probs: [0.00, 0.55, 0.30, 0.00, 0.10, 0.05]
    alpha: [1.0, 1.0, 1.0, 1.0, 15.0, 1.0]
```

计算：ESS(操纵型) = sum(alpha) = 24, ESS(配置型) = 10, 权重 = 24/(24+10) = 0.71。建仓概率 = 0.40×0.71 + 0.30×0.29 = 0.37。

### 4. 领域文档更新

**`CONTEXT.md` § 博弈参与者**：

删除操纵型主力与配置型主力的单独条目，替换为：

```markdown
**主力**：
以价格行为与筹码控制为手段的资金。包含短周期操纵型（游资、同质化量化）与长周期配置型（价值机构、长线外资），单日资金流无法区分两者，因此在测量层合并为一类。两者行为模式的差异可通过序列特征观测（如连续多日小单吸筹判定配置型），但不体现在 W 矩阵的参与者维度中。

```

保留「羊群散户」条目不变。删除「做市商」「国家队」条目（本就不是参与者）。

**`ARCHITECTURE.md` §3.1**：

参与者表格从三行缩为两行：

| 参与者 | 盈利方式 | 周期 | 信号特征 |
|---|---|---|---|
| 主力 | 价格控制与筹码博弈 | 短至长 | 大单（super/big/mid）；短周期者信号可伪造，长周期者难伪装 |
| 羊群散户 | 情绪与从众 | — | 被收割方，同时是反向指标 |

并在段落中说明：

> 主力包含操纵型（游资、同质化量化，周期短，单日成交量突兀）与配置型（价值型机构、长线外资，周期长，建仓缓慢）。两者在单日资金流上均表现为大单，无法从净额区分，因此在 W 矩阵中合并为一个参与者类。序列特征（如连续五日小单吸筹 + 无拉升）可以在观测层作为配置型主力的额外证据，但不拆分 W 的参与者维度（见 ADR-0018）。

§3.2 改为「参与者各自的六种行为」，分别冻结主力与散户词表。

§4.1 W 矩阵尺寸描述从「5×3×6」改为「5×2×6」，并更新示例：

```python
W[z][participant][behavior]  # 5×2×6
# z ∈ {冰点, 启动, 发酵, 高潮, 退潮}
# participant ∈ {主力, 散户}
# behavior ∈ vocabulary(participant)
```

### 6. 标注器输出契约

个股层主力标注器（P0-5，已冻结在 `config/labeler.yaml`）继续输出主力词表中的 `(behavior)`。散户 W 行需要由散单流向与情绪证据生成散户词表标签；没有该证据时保持先验，不得把主力标签直接写入散户行。

板块层标注器（P0-4，规则待定）输出保持 `(sentiment_state)`，不涉及参与者维度——板块情绪是状态，不是行为。

散户证据归属可先用资金流分档判定参与者：

```python
if main_in_flow > 0 and (super_in_flow + big_in_flow) / main_in_flow > 0.6:
    participant = "主力"
else:
    participant = "散户"
```

阈值 0.6 是初始值，后续可根据实测分布调整。

## 何时重新拆分

如果未来满足以下**全部**条件，可以考虑重新拆分为三参与者：

1. 龙虎榜数据接入（P4）且覆盖率达到 15% 以上（当前 1–2%）
2. 序列模式标注器实现（识别「连续吸筹」vs「拉高派发」）
3. 三参与者下每格样本量 ≥ 50（需运行 18 个月以上）
4. 用户明确需要操纵型与配置型的细粒度区分用于特定策略

在此之前，二参与者设计是架构能力与测量层对齐的最优解。
