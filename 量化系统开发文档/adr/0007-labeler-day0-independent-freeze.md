# 事后标注器 Day 0 上线，两层独立冻结

HMM 前向滤波的转移矩阵从人工先验出发，数据驱动的更新依赖标注标签。情绪周期位置（板块层）和主力行为（个股层）是隐状态，运行时无法直接观测，只能事后从价格数据推断——例如「出货」的冻结定义是「当日涨跌幅在 ±2% 内 + 前向五日板块超额收益 ≤ -3% + 放量 ≥ 1.20 + 上影线占振幅 ≥ 25% + 距前阻力 ≥ -2%」（ADR-0017）。标注器每晚用前视窗口（t…t+5）扫描历史，产生延迟 5 日的标签流。

标注器必须 Day 0 就跑，不能等系统"稳定了再说"。每一天不跑就是永久损失一天的标签，而这些标签是让先验向数据过渡的唯一燃料——启动越晚，冷启动期越长。

## 两个独立标注器，各自独立冻结

- **板块层标注器**：输入板块指数 OHLCV，判定情绪周期位置（冰点/启动/发酵/高潮/退潮）；板块级分歧另作为正交共识状态记录（ADR-0021）
- **个股层标注器**：输入个股 OHLCV，判定主力行为（建仓/震仓/拉升/出货/观望/狩猎止损）

两者的输入、判定规则、前视窗口长度都不同，必须独立实现。更重要的是**独立冻结与独立哈希**：每个标注器发布时计算其规则代码的哈希，该哈希连同它产生的每条标签一起存档。修改个股标注规则不会作废板块层已积累的计数，反之亦然。

> **修订（ADR-0017）**：个股层的行为枚举原文写的是「建仓/点火/派发/砸盘/观望」五个标签，与 `hmm_prior.yaml` 的 W 矩阵所用的六标签（建仓/震仓/拉升/出货/观望/狩猎止损）不一致。若照原文实现，标注器的输出无法喂进 W 矩阵。已按六标签修正，上文已是修正后的版本。六标签为冻结口径，见 ADR-0017 与 `config/labeler.yaml`。

> **修订（ADR-0017）**：本 ADR 的「独立」措辞会被读成「个股标注器不许碰任何板块数据」，那样就只能用绝对收益，而实测显示绝对口径会把行业共同冲击混进标签。澄清为：独立 = 独立的代码、规则配置、规则哈希和输出，不读取板块情绪标签、板块标注器输出或其派生统计；可以只读同日不可变的原始板块 OHLCV 作为相对收益的外生基准。防的是跨层标签泄漏与自我强化，不是禁止读取公共行情事实。

## 标注器的性质

标注器是**定义**，不是真相。它把一个抽象概念（「派发」）映射成可程序验证的条件——这个映射是人为选择，换一套映射就是另一套数据。一旦冻结，不能为了"让准确率好看"而修改规则；真正应该做的是在 ADR 里记录定义更改的原因，并重算历史标签。
