================================================================
  PA Agent 智能体部署方法（Mac 版）
  适用环境：macOS 12+ (Monterey 及以上) + Python 3.11+ 已安装
  默认数据源：富途 OpenD（由 Agent 自动下载安装，见第四步）
================================================================

【说明】
本文档供自动化 Agent 按步骤执行部署。每一步都有明确的命令和验收条件。
遇到问题时按"故障排查"章节处理。最后必须通过验收环节才能交付给用户。

【重要：OpenD 由 Agent 自己下载安装，不要让用户自己下】
Agent 负责把富途 OpenD 下载好、装好、打开到登录界面；用户只需要在登录界面
输入富途账号密码点登录（登录必须用户本人操作）。见第四步。

【重要：Mac 与 Windows 的核心差异】
1. MT5（MetaTrader 5）没有 macOS 原生版本，Mac 版默认使用"富途 OpenD"作为数据源
2. 富途 OpenD 是富途官方提供的本地行情网关（官方支持 macOS），PA Agent 通过
   futu-api 连接本机 OpenD（默认 127.0.0.1:11111）读取 K 线
3. Mac 上 PA Agent 不会自动启动 OpenD（自动启动仅 Windows 支持），必须先手动
   打开 OpenD 并完成登录，程序才能取到数据
4. pywin32 / MetaTrader5 包不支持 macOS，无需安装
5. 不需要 bat 文件，Mac 用 .command 文件（双击即可运行）
6. pyproject.toml 中 MetaTrader5 和 pywin32 标记了 sys_platform == 'win32'，
   macOS 下 pip 会自动跳过；futu-api 无平台限制，macOS 下会自动安装
7. 项目代码已做了平台兼容：数据源通过 factory.py 工厂创建，Mac 下默认使用 Futu（OpenD）

【重要：富途 OpenD 下载地址（Agent 自己下，不要甩给用户）】

  Mac 官方直链（自动指向最新版）：
    https://www.futunn.com/download/fetch-lasted-link?name=opend-macos

  官网下载页（直链失效时回退到这里）：
    https://support.futunn.com/topic464?lang=zh-cn&from_platform=1

  - 只从富途官网下载，不要用第三方下载站 / 网盘里的包
  - macOS 版是通用二进制，本身就同时支持 Intel 和 M 系列，不需要另找 ARM 版
  - 富途 OpenD 不需要 API Key，但需要一个富途账号（牛牛号 / 邮箱 / 手机号）登录

【重要：项目路径】
本文档中 PROJECT_ROOT 代表 PA_Agent 项目的根目录。
执行前必须先确定项目实际路径，后续所有命令中的 PROJECT_ROOT 都替换为实际路径。
例如：用户项目在 ~/Desktop/PA_Agent，则 PROJECT_ROOT = ~/Desktop/PA_Agent
      用户项目在 /Users/张三/Projects/PA_Agent，则 PROJECT_ROOT = /Users/张三/Projects/PA_Agent

确定方法：找到项目中存在 pa_agent/main.py 和 pyproject.toml 的那个目录，就是 PROJECT_ROOT。

【重要：不使用虚拟环境】
本方案直接将依赖安装到系统 Python，不创建虚拟环境。
原因：用户双击 .command 文件运行程序，虚拟环境会增加不必要的复杂度和闪退风险。
只要系统 Python 是专门给本程序用的，就不会有冲突问题。

【重要：Shell 说明】
本文档所有命令均使用 bash/zsh 语法（macOS 默认终端）。

================================================================
  第零步：确认当前系统是 macOS
================================================================

执行以下命令：

  uname -s

预期输出：Darwin

若输出不是 Darwin，说明当前不是 macOS，请使用 Windows 版部署文档。

================================================================
  第一步：确认前置条件
================================================================

执行以下命令，确认 Python 已就绪：

  python3 --version

预期输出：Python 3.11.x 或更高版本（3.12、3.13 均可）

若输出"command not found: python3"，说明 Python 未安装。
解决方法：

  方案 A — 官方安装包（推荐）：
    访问 https://www.python.org/downloads/ 下载 Python 3.11+ 安装包
    安装时勾选"Install for all users"

  方案 B — Homebrew：
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
    brew install python@3.13

若 python3 存在但 python 不存在，创建软链接：
  sudo ln -sf $(which python3) /usr/local/bin/python

  注意 2：tvDatafeed 是 TradingView 备选数据源的核心依赖，

【故障排查】

问题 1：pip install 网络超时 / ConnectionError
解决：
  方案 A - 换清华源（已在上面命令中使用）：
    pip3 install -e . -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn

  方案 B - 换阿里云源：
    pip3 install -e . -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com

  方案 C - 逐个安装（某个包卡住时单独装）：
    pip3 install PyQt6 -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
    pip3 install pyqtgraph -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
    ... 依次安装每个包

问题 2：PyQt6 安装后报 "DLL load failed" 或 import 失败
解决：
  macOS 上 PyQt6 依赖较新版本的 macOS 和 OpenGL：
  - 确认 macOS 版本 >= 12.0 (Monterey)
  - 若使用 Homebrew Python，尝试：
    brew reinstall python@3.13
    pip3 install --force-reinstall PyQt6
  - 若仍然失败，安装 Qt 依赖：
    brew install qt

问题 3：tvDatafeed 安装失败（git clone 超时 / 网络不可达）
说明：tvDatafeed 是 TradingView 备选数据源的核心依赖，
  从 GitHub 安装（git+https://github.com/rongardF/tvdatafeed.git），
  国内网络可能无法直接克隆。只使用富途 OpenD 时这个问题不影响部署。
解决：
  方案 A — 配置 git 代理（如果已有代理）：
    git config --global http.proxy http://127.0.0.1:7890
    git config --global https.proxy http://127.0.0.1:7890
    pip3 install git+https://github.com/rongardF/tvdatafeed.git

  方案 B — 手动下载 + 本地安装：
    浏览器打开 https://github.com/rongardF/tvdatafeed
    → Code → Download ZIP → 解压到本地
    → cd 到解压目录 → pip3 install .

  方案 C — 使用 gitee 镜像（如存在）：
    搜索 gitee 上是否有 tvdatafeed 镜像仓库，克隆后用 pip3 install . 安装。

问题 3.5：tvDatafeed 安装后，TradingView 数据拉取全部报 "Connection to remote host was lost"
原因：tvDatafeed 2.1.0 存在一个已知 bug —— 其 WebSocket headers 参数传的是 JSON 字符串
  而非 Python dict，导致 websocket-client ≥1.8 版本拒绝握手（HTTP 400）。
解决：找到 tvDatafeed 安装目录下的 main.py，修改一行代码。

  定位文件：
    python3 -c "import tvDatafeed; import os; print(os.path.dirname(tvDatafeed.__file__))"
  输出类似：/opt/homebrew/lib/python3.13/site-packages/tvDatafeed

  编辑该目录下的 main.py，找到第 35 行附近的：
    __ws_headers = json.dumps({"Origin": "https://data.tradingview.com"})
  改为：
    __ws_headers = {"Origin": "https://data.tradingview.com"}

  改完后验证（使用 daily interval，避免分钟线超时干扰验证结果）：
    python3 -c "from tvDatafeed import TvDatafeed, Interval; df = TvDatafeed().get_hist('XAUUSD', 'OANDA', Interval.in_daily, n_bars=2); print('OK:', len(df), 'bars')"
  预期输出：OK: 2 bars

  说明：此 bug 仅在 websocket-client ≥1.8 时触发。如果你用的是旧版 websocket-client，
  可能不受影响，但建议一并修复以兼容未来升级。

问题 3.6：tvDatafeed 安装后数据拉取变慢，切换品种/周期要等 40 秒甚至更久
原因：tvDatafeed 2.1.0 的 get_hist() 在每次调用时都会新建 WebSocket 连接，但从不关闭
  上一个连接——持续使用会积累大量半开放连接，触发 TradingView 速率限制。
  PA_Agent 项目已在 pa_agent/data/tradingview.py 中对此进行修复（无需改 tvDatafeed 源码）：
  1. 每次 get_hist() 调用完成后自动关闭 socket，不再泄漏连接
  2. 切换品种/周期时主动关闭当前 socket，立即中断挂起的请求（不再排队等超时）
  3. 单次请求超时从 15 秒缩短至 10 秒，且不再自动重试（避免超时翻倍）
  这些修复已包含在项目代码中，pip install -e . 后即生效，无需额外操作。

  注意：即使有上述修复，TradingView 匿名（nologin）模式下仍受 IP 速率限制。
  若经常拉取失败，最有效的解决方案是在 GUI 设置中填入 TradingView 账号用于登录。

问题 4：pyqtgraph 与 PyQt6 版本不兼容
解决：指定兼容版本：
    pip3 install pyqtgraph>=0.13 -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn

问题 5：numpy 版本冲突
解决：
    pip3 install numpy>=1.26 -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn

问题 6：macOS 上 PyQt6 窗口无法显示 / 黑屏
解决：
  - 确认没有设置 QT_QPA_PLATFORM 环境变量（macOS 上不需要）
  - 若通过 SSH 远程运行，需要 X11 转发或 VNC，不支持 headless
  - 若使用 macOS 安全策略阻止了 Python 打开窗口：
    系统偏好设置 → 安全性与隐私 → 允许从以下位置下载的 App → 允许 Python

问题 7：futu-api 安装失败 / import futu 报错
解决：
  - 单独安装（指定清华源）：
    pip3 install futu-api -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
  - 若报 protobuf 版本冲突（其他包要求 protobuf 4.x/5.x）：
    futu-api 需要 protobuf 3.x，属正常依赖；先满足 futu-api：
    pip3 install "protobuf<4" futu-api
  - 若报编译 / 找不到轮子，先按第二步升级 pip 后重试

问题 8：import futu 成功但连接报版本不匹配
解决：OpenD 与 futu-api 版本尽量配套（都用最新版）：
    pip3 install --upgrade futu-api
  同时按第四步重新下载最新版 OpenD。

================================================================
  第四步：Agent 下载安装富途 OpenD，并打开到登录界面
================================================================

本步骤由 Agent 全程执行，不要甩给用户：下载 → 解压 → 取可视化 GUI 版 → 装到
"应用程序" → 打开到登录界面。装好后只让用户做一件事：输入富途账号密码点登录。

【先记住两点，能避开最大的两个坑】
1) 官方 Mac 包是通用二进制，本身就同时支持 Intel 和 M 系列（ARM），
   不需要另找"ARM 专用版"——那种东西不存在，别去找。
2) 官方 tar.gz 里同时含"可视化 GUI 版"和"命令行版"，要装的是 GUI 版
   （里面是 .dmg）。装错成命令行版的话，用户看到的是黑框命令行、没有登录界面。

----------------------------------------------------------------
4.1 Agent 下载
----------------------------------------------------------------

  curl -L --fail --retry 3 -o /tmp/futu_opend_mac.tar.gz \
       "https://www.futunn.com/download/fetch-lasted-link?name=opend-macos"

约 400MB，需要等几分钟。下载完确认下到的是完整压缩包：

  ls -la /tmp/futu_opend_mac.tar.gz

若 curl 报 404 / 下载失败，说明直链变了：改用官网下载页，把链接发给用户，
请他下载 MacOS 版（可视化 OpenD）后把文件路径告诉你，再继续 4.2：
  https://support.futunn.com/topic464?lang=zh-cn&from_platform=1

----------------------------------------------------------------
4.2 Agent 解压并安装（认准 GUI 版）
----------------------------------------------------------------

  mkdir -p /tmp/futu_opend && tar xzf /tmp/futu_opend_mac.tar.gz -C /tmp/futu_opend
  find /tmp/futu_opend -maxdepth 2 -not -name "._*"

会看到两个并列目录，版本号以实际为准：

  Futu_OpenD-GUI_<版本>_Mac/    ← 可视化版（要装这个，里面是 .dmg）
  Futu_OpenD_<版本>_Mac/        ← 命令行版（不要装）

挂载 GUI 版的 dmg 并装进"应用程序"：

  DMG=$(ls /tmp/futu_opend/Futu_OpenD_*/Futu_OpenD-GUI_*/*.dmg | head -1)
  hdiutil attach "$DMG" -nobrowse
  SRC=$(ls -d /Volumes/Futu_OpenD-GUI_*/*.app | head -1)
  rm -rf "/Applications/$(basename "$SRC")"
  cp -R "$SRC" /Applications/
  xattr -dr com.apple.quarantine "/Applications/$(basename "$SRC")"
  hdiutil detach /Volumes/Futu_OpenD-GUI_* -quiet

验收：确认装进去的是 GUI 应用

  ls -d /Applications/Futu*.app

预期输出形如 /Applications/Futu_OpenD-GUI_<版本>_Mac.app。
如果 /Applications 里出现的是不带 GUI 前缀的 FutuOpenD.app，就是装错成命令行版了：
删掉它（rm -rf /Applications/FutuOpenD.app），回到 4.2 开头确认取的是
Futu_OpenD-GUI_* 那个目录下的 .dmg，重装一次。

----------------------------------------------------------------
4.3 Agent 打开到登录界面
----------------------------------------------------------------

  APP=$(ls -d /Applications/Futu*.app | head -1)
  open "$APP"

预期：OpenD 图形界面弹出，停在登录界面。

若被 macOS 拦（提示"无法验证开发者"/"已损坏，无法打开"），先清隔离属性再开；
仍被拦就让用户右键（Control+点击）应用 → 打开 → 打开：

  xattr -dr com.apple.quarantine "$APP" && open "$APP"

若弹窗要求输入 Mac 开机密码授权，让用户输一下（系统行为，Agent 无法代填）。

----------------------------------------------------------------
4.4 让用户登录（唯一必须用户本人做的一步）
----------------------------------------------------------------

对用户说：
"富途 OpenD 已经装好并打开了，请在刚弹出的窗口里输入富途账号（牛牛号 / 邮箱 /
手机号）和密码点登录；手机号登录要选国家地区代码（大陆 +86）；如果提示要短信
验证码就填一下；如果这个账号第一次在本机登录，会先让你做一次问卷评估与协议确认，
做完再点一次登录。登录成功后窗口会显示账号信息和'行情权限'，你跟我说一声。"

提醒用户：这个窗口在跑 PA Agent 期间一直开着；本程序只要"行情"能力，不要做交易解锁。

----------------------------------------------------------------
4.5 Agent 验收：已登录且能连上
----------------------------------------------------------------

  lsof -nP -iTCP:11111 -sTCP:LISTEN

预期：有进程在 11111 端口 LISTEN。没有输出通常是用户还没登录成功（登录前不监听），
或窗口被关了，回 4.3 / 4.4 处理；也可能是端口被改过，要让用户在 OpenD 界面确认
"API 端口"是 11111、"监听地址"是 127.0.0.1（改过就在 PA Agent 设置里填成一致）。

再确认 SDK 能连上并已登录行情：

  python3 -c "
from futu import OpenQuoteContext
ctx = OpenQuoteContext(host='127.0.0.1', port=11111)
ret, data = ctx.get_global_state()
print('ret =', ret)
print('data =', data)
ctx.close()
"

预期：ret = 0，data 中 qot_logined 为 True。
若报 No module named 'futu'，回第三步装 futu-api。

【故障排查】
- 用户看到的是黑框命令行、没有登录界面：装成命令行版了，见 4.2 验收里的纠正办法
- 拉不到数据 / 订阅失败 / 无权限：在 OpenD 界面确认已登录且有该市场行情权限，
  换有权限的品种试（SH.600519 / HK.00700 / US.AAPL）；富途行情权限会被其他设备
  顶号抢占，确认账号没在手机或牛牛客户端同时登录
- 端口 11111 被占用：在 OpenD 界面改成 11112，并在 PA Agent 设置里填相同端口
- 登录失败：手机号要带国家代码（+86）；首次登录需先完成问卷评估与协议确认
- 行情权限说明：https://openapi.futunn.com/futu-api-doc/intro/authority.html
- 用户不想装 OpenD：可跳过本步改用 TradingView 数据源（无需本地网关，但国内直连
  可能不稳、匿名模式限流）。做法：跳过第四步，把第五步中 factory.py / settings.py
  的默认值改成 "tradingview"、last_symbol 改成 "XAUUSD"，并按"附：TradingView
  备选数据源使用说明"与第三步问题 3.5 / 3.6 处理。

================================================================
  第五步：修改项目代码，使 Mac 默认使用富途 OpenD
================================================================

Mac 版需要修改以下文件，使程序默认使用"富途 OpenD"数据源而非 MT5。

5.1 修改 pyproject.toml — 无需修改
  pyproject.toml 中 MetaTrader5 和 pywin32 已标记 sys_platform == 'win32'，
  macOS 下 pip install -e . 会自动跳过这两个包；futu-api 已在依赖列表中，
  macOS 下会自动安装。无需手动修改。

5.2 修改 pa_agent/data/factory.py — 关键修改
  将 normalize_data_source_kind() 的默认返回值从 "mt5" 改为 "futu"，

----------------------------------------------------------------
【根本原因】—— 必须先理解，再动手
----------------------------------------------------------------

三个"设置栏"入口是用 QMenuBar + QAction 构建的，位置在：

  pa_agent/gui/workspace_window.py
      _build_menu()            ← 自选股主窗口（用户日常打开的是这个）
      self.menuBar().addAction(QAction("AI 模型设置"))
      self.menuBar().addAction(QAction("飞书发送通知设置"))
      self.menuBar().addAction(QAction("其他通用设置"))

  pa_agent/gui/main_window.py
      _setup_ui() 末尾的 "── Menu bar ──" 段落，同上三个 QAction

关键点：在 macOS 上，Qt 默认会把 QMenuBar 从窗口内部"搬走"，
交给系统顶部的全局菜单栏（屏幕最上方那条 Apple 菜单栏）显示，
这个行为叫"原生菜单栏"（native menu bar / global menu bar）。
macOS 只在应用处于前台且激活时，才把菜单项渲染到屏幕顶部。
因此必然出现下面两种结果之一：

  结果 A：菜单项跑到了屏幕最顶部的系统菜单栏里，窗口内部那一栏变成空白
          → 用户以为"顶栏不显示了"
  结果 B：进程没有被识别为标准 GUI 应用（比如从非 .app 方式、从终端或
          .command 启动，且未设置 applicationName），系统菜单栏没有正确
          接管，菜单项哪儿都不显示
          → 用户以为"那一片直接不显示了"

不管哪种，表现都是"顶栏设置栏看不到"。这就是为什么用户说不清是遮挡还是消失。

----------------------------------------------------------------
【修复方案】—— 强制菜单栏回到窗口内部显示
----------------------------------------------------------------

修复思路：显式关闭 Qt 的原生菜单栏行为，让菜单栏老老实实待在窗口内部，
在所有平台（含 macOS ARM）上表现一致。

推荐做法（最干净、一行搞定、全局生效）：
在程序最开始、创建 QApplication 之前，设置应用级属性。

5A 修改 pa_agent/main.py（或项目实际的 GUI 入口文件，即 import PyQt6 的那个）

  在 import 区加入：

    import sys
    from PyQt6.QtCore import Qt

  在创建 QApplication 实例之前（必须之前，之后设置无效）加入：

    # macOS：禁用原生菜单栏，让「AI 模型设置 / 飞书发送通知设置 / 其他通用设置」
    # 这几个入口保持在窗口内部显示，而不是被系统搬到屏幕顶部的全局菜单栏。
    QApplication.setAttribute(
        Qt.ApplicationAttribute.AA_DontUseNativeMenuBar, True
    )

  典型上下文长这样：

    app = QApplication(sys.argv)          ← 后面加下面这行也不行，必须在这行之前
    app.setApplicationName("PA Agent")

  正确写法：

    QApplication.setAttribute(Qt.ApplicationAttribute.AA_DontUseNativeMenuBar, True)
    app = QApplication(sys.argv)
    app.setApplicationName("PA Agent")

如果 5A 因为入口文件结构特殊不方便改，用下面的兜底做法（两个窗口各改一处）：

5B-1 修改 pa_agent/gui/workspace_window.py 的 _build_menu()

  找到：
    def _build_menu(self) -> None:
        menu = self.menuBar()
        ai_action = QAction("AI 模型设置", self)

  改为：
    def _build_menu(self) -> None:
        menu = self.menuBar()
        # macOS：菜单项必须留在窗口内部。不关闭原生菜单栏时，Qt 会把
        # 这三个设置入口搬到系统全局菜单栏，窗口顶部会变成一片空白。
        menu.setNativeMenuBar(False)
        ai_action = QAction("AI 模型设置", self)

  即：在 menu = self.menuBar() 之后立刻补一行 menu.setNativeMenuBar(False)

5B-2 修改 pa_agent/gui/main_window.py 的菜单栏段落

  找到（_setup_ui() 末尾）：
        menu_bar: QMenuBar = self.menuBar()  # type: ignore[assignment]

        # 1. AI 模型设置 — 点击直接弹对话框（无下拉）

  改为：
        menu_bar: QMenuBar = self.menuBar()  # type: ignore[assignment]
        # macOS：同上，禁用原生菜单栏，保证设置入口显示在窗口内部。
        menu_bar.setNativeMenuBar(False)

        # 1. AI 模型设置 — 点击直接弹对话框（无下拉）

  即：在 menu_bar = self.menuBar() 之后立刻补一行 menu_bar.setNativeMenuBar(False)

说明：5A 与 5B 二者选一即可，不要重复加。推荐 5A（覆盖面最全）；
如果 5A 改了仍无效，再加 5B 作为双保险。

【故障排查】
----------------------------------------------------------------

问题 A1：已加 AA_DontUseNativeMenuBar，但窗口顶部仍是空白
原因 1：setAttribute 写在了 QApplication(...) 之后 —— 属性必须在实例化之前设置
解决  ：把 setAttribute 移到 app = QApplication(sys.argv) 之前
原因 2：入口文件不是 pa_agent/main.py，改了没生效的文件
解决  ：搜索真正的入口：
        grep -rn "QApplication(" PROJECT_ROOT/pa_agent
        在创建 QApplication 的那个文件里加
原因 3：外加 5B 后仍无效
解决  ：把 5A 和 5B 同时加上（一个管应用级、一个管窗口级），仍无效时
        在启动前设环境变量验证：
          export QT_MAC_DISABLE_NATIVE_MENUBAR=1
          python3 run.py
        若这样能显示，说明确实只是原生菜单栏接管问题，回查上面的改动是否生效。

问题 A2：菜单栏显示了，但按钮点击没反应 / 对话框弹不出来
原因：这一步不是平台问题，是信号连接断了
解决：检查 _build_menu() / _setup_ui() 中 QAction.triggered.connect(...)
      是否被注释或改动，确认连接的是 _open_ai_model_settings /
      _open_feishu_settings / _open_general_settings（主窗口侧为
      _open_ai_model_settings_dialog 等），不要误删

问题 A3：三个入口显示了，但被图表区域压住 / 只露出一部分
原因：菜单栏虽然回到窗口内部，但中央控件高度把位置挤掉了
解决：本项目的窗口尺寸已按屏幕可用区域计算（WorkspaceWindow 用
      screen.availableGeometry() 的 90% × 85%），一般不会发生；
      若确有，检查是否被 setMenuWidget / 自定义标题栏覆盖，
      或确认没有给 centralWidget 设置过大的 minimumHeight

问题 A4：双击 .command 启动时菜单栏消失，但终端 sudo python3 run.py 启动时正常
原因：这是 macOS 对"未做 .app 打包的脚本应用"的典型差异，与原生菜单栏
      接管逻辑叠加导致
解决：加 5A 的应用级属性即可解决；同时建议在入口文件里补一行：
        app.setApplicationName("PA Agent")
        app.setApplicationDisplayName("PA Agent")
      让系统正确识别本进程为 GUI 应用

1. 前置条件
   富途 OpenD 必须先启动并完成登录，且在本程序运行期间保持开启。
   Mac 上 PA Agent 不会自动启动 OpenD（自动启动仅 Windows 支持）。
   下载地址（官网）：
   https://support.futunn.com/topic464?lang=zh-cn&from_platform=1

2. 连接参数
   默认连接 127.0.0.1:11111（与 OpenD 可视化界面右侧的"监听地址/API 端口"一致）。
   如需修改：GUI 设置页 → Futu OpenD → 主机 / 端口，
   或直接改 config/settings.json 中的 futu.opend_host / futu.opend_port。

3. 品种代码格式（富途代码 = 市场.代码）
   - A 股：SH.600519（贵州茅台）、SZ.000001（平安银行）、BJ.xxxxxx
   - 港股：HK.00700（腾讯控股）
   - 美股：US.AAPL
   - A 股也可以只输入 6 位数字（如 600519），程序会自动补全为 SH.600519；
     若补全的市场不对，用输入框左侧的交易所下拉框指定 SH / SZ
   - 输入框右侧的"?"按钮有代码格式帮助

4. 支持的周期
   1m / 3m / 5m / 10m / 15m / 30m / 1h / 2h / 3h / 4h / 1d / 1w / 1M

5. "获取数据"按钮
   富途数据源不会在启动时自动拉取数据。
   需手动点击工具栏中的"获取数据"按钮，之后会进入持续刷新模式。
   切换品种或周期后，RefreshLoop 会在下一个 tick 自动使用新的品种/周期拉取，
   无需再次点击"获取数据"按钮。

6. 刷新间隔
   设置页"刷新间隔(毫秒)"（refresh_interval_ms）默认 1000ms。
   富途数据来自本机 OpenD，不像 TradingView 匿名模式那样有 IP 限流，
   但建议不要低于 1000ms，以免无谓占用行情订阅额度。

7. 切换品种有 1 分钟最小订阅间隔
   富途要求同一合约的 K 线订阅至少保持 60 秒才能退订。
   程序已做延后退订处理：快速来回切换品种/周期时，页面上可能短暂没有数据，
   属于正常现象，稍等即可恢复。

8. 行情权限
   没有权限的市场/品类，K 线拉取会失败并给出具体错误。
   行情权限可在 OpenD 界面查看，官方说明：
   https://openapi.futunn.com/futu-api-doc/intro/authority.html

9. 首次取数可能较慢
   OpenD 首次连接、首次订阅某市场行情时会做一次初始化，稍等几秒属正常。

10. 内嵌"二阶博弈"模块
   "二阶博弈 → 设置"中的市场数据源默认就是"Futu OpenD（默认）"，
   使用同一组 OpenD 主机/端口；其板块查询需要填写富途返回的板块代码。

================================================================
  附：TradingView 备选数据源使用说明
================================================================

说明：Mac 版默认数据源已改为富途 OpenD。如需改用 TradingView（不依赖本地网关，
但国内直连可能不稳定、匿名模式有限流），在界面数据源下拉框中切换到 TradingView，
或把 config/settings.json 的 general.last_data_source 改为 "tradingview" 后重启。

1. 刷新间隔设置
   在 GUI 设置页面中可配置"刷新间隔(毫秒)"（refresh_interval_ms），默认 1000ms。
   该值在 TradingView 数据源下同样生效，但注意：TradingView nologin 模式
   对高频请求有限流，建议日线设 3000-5000ms，分钟线可设 1000-2000ms。
   PA_Agent 内置了防重叠调用和指数退避机制，连续失败时会自动延长等待时间。

2. "获取数据"按钮
   TradingView 数据源不会在启动时自动拉取数据。
   需手动点击工具栏中的"获取数据"按钮，之后会进入持续刷新模式。
   切换品种或周期后，RefreshLoop 会在下一个 tick 自动使用新的品种/周期拉取，
   无需再次点击"获取数据"按钮——切换会立即中断当前挂起的请求，
   而不是等上一个请求的超时周期结束。

3. 交易所选择
   下拉框中的交易所已按类别标注（如 SSE（A股）、HKEX（港股）、BINANCE 等），
   加密类交易所无后缀标注。
   不确定交易所时可选择"（自动）"，程序会自动探测。

4. 匿名模式限速说明
   未配置 TradingView 账号时使用匿名（nologin）模式，TradingView 会对匿名 IP
   施加请求限制，尤其是小周期（1m、5m）拉取更容易触发。
   若频繁出现超时，最有效的解决方案是在设置界面填入 TradingView 账号：
   设置 → TradingView → 用户名 / 密码（凭证加密存储，不会明文保存）。

  附：Mac 特有问题

Q: 窗口顶部的「设置栏」不显示（看不到 AI 模型设置 / 飞书发送通知设置 / 其他通用设置）
A: 这是 Mac（尤其 M 系列 Apple Silicon 机型）的已知适配问题，必须改代码后才会正常显示。
   现象：程序能正常打开、图表和 AI 面板都正常，但窗口顶部那一栏三个设置入口
   整片看不到（用户容易描述成"被遮挡了"或者"那一片直接不显示了"，其实是同一原因）。
   原因：这三个入口是 QMenuBar 实现的，macOS 上 Qt 默认会把菜单栏搬去屏幕最顶部的
   系统全局菜单栏，导致窗口内部那一栏变空，或系统未接管时哪儿都不显示。
   解决：让 Agent 按正文【附加必做：Mac 顶栏「设置栏」显示适配】章节处理，核心是在
   创建 QApplication 之前加一行：
     QApplication.setAttribute(Qt.ApplicationAttribute.AA_DontUseNativeMenuBar, True)
   并在 workspace_window.py 的 _build_menu()（以及 main_window.py 的菜单栏段落）中
   补一行 menu.setNativeMenuBar(False)。改完后窗口内部顶部即可看到三个设置入口。
   验证：改完必须人工肉眼确认三个按钮都出现、点击都能弹出对话框——
   只做 import 检查发现不了这个问题。

Q: 找不到修改 DeepSeek API Key 的地方
A: 入口在窗口顶部那一栏的「AI 模型设置」按钮里。如果看不到这一栏，
   先按上一条（顶栏设置栏不显示）处理，修复后即可点击进入。

Q: macOS 上没有 MT5，怎么办？
A: Mac 版不使用 MT5，默认使用富途 OpenD 作为数据源（富途官方本地行情网关，
   Mac 原生支持），覆盖 A 股、港股、美股等市场。
   也可以切换到 TradingView（备选数据源）。
   如果必须使用 MT5，可以通过虚拟机（Parallels Desktop / VMware Fusion）运行 Windows。

Q: 富途 OpenD 是什么？必须装吗？
A: 是富途官方提供的本地行情网关。Mac 版默认数据源就是它，所以必须先装好、启动并登录，
   程序才能取到 K 线。安装由 Agent 自动完成（见第四步），用户只需要在登录界面
   输入富途账号密码点登录。
   如果用户不愿意装，可改用 TradingView 数据源（见第四步故障排查最后一条）。

Q: 富途 OpenD 的 M 系列（ARM）版本要去哪里下载？
A: 不存在单独的 ARM 版本。官方 Mac 包是通用二进制，本身就同时包含 x86_64 与 arm64
   两套切片，M 系列芯片上会原生运行 arm64，不需要任何额外处理。
   Agent 直接下 opend-macos 这一个包就行，不要去搜"arm64 专用版"。

Q: 富途 OpenD 提示"无法验证开发者"或"已损坏，无法打开"
A: 先去掉隔离属性再打开（注意应用名以 /Applications 下实际名称为准，GUI 版通常带
   Futu_OpenD-GUI_ 前缀）：
   APP=$(ls -d /Applications/Futu*.app | head -1)
   xattr -dr com.apple.quarantine "$APP"
   open "$APP"
   若仍被拦：右键（Control+点击）应用 → 打开 → 打开。

Q: 装完之后只有黑框命令行，没有登录界面
A: 装成命令行版了。官方包里有"可视化 GUI 版"和"命令行版"两个文件夹，可视化版才是
   带登录界面的（安装包是 .dmg）。删掉装错的再重装：
   rm -rf /Applications/FutuOpenD.app
   然后按第四步 4.2，取 Futu_OpenD-GUI_* 目录下的 .dmg 安装。

Q: OpenD 显示已登录，但程序里拉不到数据
A: 按顺序检查：
   1. lsof -nP -iTCP:11111 -sTCP:LISTEN 确认 OpenD 在监听，端口与程序设置一致
   2. OpenD 界面确认已登录、且该市场有行情权限（换 SH.600519 / HK.00700 / US.AAPL 试）
   3. 品种代码格式是否为"市场.代码"（如 SH.600519），不要用 MT5 的 XAUUSDm
   4. 确认已点击工具栏"获取数据"按钮（富途数据源启动时不自动拉取）
   5. 账号是否被其他设备顶号（富途行情权限有抢占机制）

Q: macOS 上 PyQt6 窗口字体模糊
A: 如果使用 Retina 显示器，PyQt6 通常会自动适配。若仍然模糊：
   在终端运行前设置环境变量：
   export QT_SCALE_FACTOR=1
   python3 run.py

Q: macOS 上双击 .command 文件提示权限被拒绝
A: 终端执行：
   chmod +x "PROJECT_ROOT/运行智能体.command"
   若提示"无法验证开发者"：
   xattr -d com.apple.quarantine "PROJECT_ROOT/运行智能体.command"

Q: macOS 上 Python 路径问题（python vs python3）
A: macOS 自带 Python 2（python 命令），安装 Python 3 后命令为 python3。
   run.py 中使用的是 sys.executable，会自动使用正确的 Python。
   .command 文件中写的是 python3 run.py，确保调用 Python 3。

Q: TradingView 数据拉取超时（改用 TradingView 数据源时）
A: 常见原因和处理顺序：
   1. 先确认 tvDatafeed headers bug 已修复（见第三步 问题 3.5）
   2. 检查网络能否访问 TradingView（国内直连可能需要代理）
   3. 小周期（1m/5m）更容易触发 TradingView 匿名限速，切换到 15m 以上测试
   4. 长期超时的根本解决方案：在设置界面配置 TradingView 账号登录

Q: API 调用报网络错误
A: 检查网络连接；若使用代理需确认代理可用；确认 API Key 和 Base URL 配置正确。

Q: config/settings.json 损坏
A: 删除该文件，程序重启会自动生成默认配置（默认数据源为富途 OpenD）：
   rm "PROJECT_ROOT/config/settings.json"

Q: 日志在哪里
A: PROJECT_ROOT/logs/pa_agent.log
